# ADR 0012：签名标签发版与安全客户端更新

- 日期：2026-10-13
- 状态：proposed
- 实现范围：用户已要求继续实现 GitHub Releases 与桌面更新的本地能力；本文的远程发行治理、密钥配置和三系统正式验收仍需落地，不能将 proposed 视为全部验收完成。

## 背景

macOS、Windows、Linux 原生采集客户端需要可验证的发行链，同时必须保留会议录音、离线队列和后端已持久化内容。直接调用安装器可能退出进程，仅凭“没有正在显示的录音”不足以确认安全。

## 建议与当前实现

采用 GitHub Releases，使用独立的 OpenPGP 标签签名、OS 代码签名和 Tauri updater 签名。签名标签锚定源码提交，四目标构建汇总完整制品后创建 draft，再通过受保护任务发布不可变 Release。清单发现地址稳定，资产地址固定到具体版本。

客户端使用官方 updater 的检查、下载与安装分步接口。默认自动检查，自动下载/安装分别选择。Rust 保有安装锁与采集权限请求锁，安装前同时核对全量本地队列、最新界面状态、实际原生采集和服务端停止/ACK 屏障；缺少任一证据则拒绝安装。

首轮 stable 自动更新，Linux 仅 AppImage；没有可信更新源的旧 Alpha 先手动安装新基线。后端与客户端相邻版本兼容是发行前置条件，不在更新器内迁移会议领域数据。

## 代价与保留问题

四目标全部成功才发布会降低发行速度，但避免 stable 清单缺平台。账号内其他暂停会议会阻止当前客户端安装，直到后续设计可信会话归属。公开 GitHub 下载依赖网络可达性，私有分发、镜像、灰度、差分、健康检查和自动回滚未实现。

OS 签名、公证、密钥恢复和真实已安装应用升级尚未验收。开发场景中的签名替身更新不证明 Windows/Linux 或正式 Mac 应用升级成功。

## 2026-10-13 交互修订

本地实现将更新策略收敛为三档下拉（手动检查、自动检查、自动检查并后台下载），安装必须显式点击重启更新；旧自动安装偏好强制关闭。macOS 菜单栏复用同一更新控制器，并保留可信源、状态新鲜度、录音/暂停/补传和后端停止水位门禁。远程治理与正式签名验收状态保持 proposed。
