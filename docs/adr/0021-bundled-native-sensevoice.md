# 0021 应用随包交付原生 SenseVoice

状态：proposed。日期：2026-10-25。用户已明确确认本轮完整离线包、原生 ONNX/SenseVoice 路线与安装器视觉稿；本文记录选择，决策归档状态沿用项目约定。

## 背景与选择

[0019](0019-funasr-sensevoice.md) 的外部 FunASR 服务需要用户管理 Python、模型和进程。用户要求应用具备自带模型能力。Windows x64 与 macOS arm64 包内包含 SenseVoiceSmall INT8、Silero VAD 和 sherpa-onnx 原生运行时，保留外部 FunASR 为高级选项，不打包整个 Python 框架。

由桌面私有后台通过 stdio 管理单个推理子进程：首次转录加载，串行推理，空闲三分钟卸载；异常后后续请求可重启；关闭主窗口继续常驻，真正退出封闭新请求并回收子进程。资源下载仅发生在构建时，固定模型 revision、npm SRI 和数据摘要，权重协议与软件许可分别保留在包内。

复用现有连续批次、ACK、lease/fence、转录版本和溯源，不改音频传输协议。VAD 用于拒绝静音，解码保留批次完整上下文。迁移仅针对旧默认无鉴权本机服务配置；所有记录恢复后才提交 provider，确保中断可重入。人工修订保留，不自动回退到云端，不制造模拟结果。

## 后果与验证边界

安装包增大约数百 MB，启动推理需要 CPU 与内存。本地能力覆盖转录；纪要仍使用当前配置的云端模型，完整会议工作流并非全离线。当前不含本地热词、说话人分离或新本地纪要模型。

公开中文、英文、静音样本已在 Mac 原生打包资源与实际 App 中验证；INT8 与 Python 完整权重在英文 gold/code 等词存在已观察到的差异，样本非空不能证明准确率。本轮 Windows、实际安装包和发布证据见后续版本回执；真实音频设备、长会议、噪声和多人场景独立保留。后续若优化量化或批次边界，应使用固定音频身份和盲标数据集比较，避免对两个样本过拟合。
