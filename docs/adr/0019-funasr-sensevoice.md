# 0019 FunASR 服务与 SenseVoice 批次转录

状态：proposed。日期：2026-10-24。用户已授权本轮 FunASR＋SenseVoice 接入；本文记录实施选择，架构决策状态仍待后续维护。

## 依据

在 M4 Pro 上真实识别通过，但将同一音频按原生首包 0.4 秒、后续 1 秒独立识别，两个中文短样本字符错误率为 23.08% / 25%，完整语句均为 0%。直接复用逐包通用 HTTP provider 不满足本轮质量目的。

## 选择

增加可选 FunASR 兼容转录 provider，默认 SenseVoice，独立配置服务地址、模型和可选网关密钥。由外部本机或私有服务管理推理环境与模型，App 本轮不捆绑 Python 或模型二进制。

独立批次处理模块从已持久化音频聚合连续范围。按 record/source/epoch 隔离；保留原始 sequence、偏移、水位和 hash，不改变录音包格式或持久 ACK。静音包边界优先切分，墙钟等待及大小有上限；暂停和停止解除批次等待并排空短尾，缺包等待补传。

批次以 lease/fence 和 generation 防止并发重复提交及删除后的迟到结果；配置改变会拒绝旧服务结果。复用批次转录提交，附带 provider/model 与所有原始包标识，引用使用稳定片段 ID / revision。保留旧豆包批次接口默认语义、人工编辑保护、现有 ASR＋LLM 与原音纪要方式。

失败明确保留录音和重试状态，不模拟文字，不自动发送到其他服务。SenseVoice 不是原生流式模型，不在 UI 宣称 streaming partial；不推断说话人或逐词时间戳。

## 代价与验证

会中转录具有批次等待；连续无停顿时可能在有界窗口切分。CPU、双路吞吐和真实会议准确率必须实测；短样本不能替代长会议。精细 VAD、重叠上下文对齐、ONNX 加速、模型包与签名自动管理作为后续独立范围。

回归覆盖真实 multipart 契约、短包聚合、大小与等待上限、静音、双来源、幂等、租约、缺包、暂停/结束排空、配置切换、错误恢复及人工版本；本机实际模型和原生 App 验收另留证。
