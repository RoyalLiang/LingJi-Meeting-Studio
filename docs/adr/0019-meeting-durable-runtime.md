# ADR 0019：以 Pi Durable 承接会议助手执行与恢复

2026-10-31。状态：**proposed，设计与实施计划待确认**。本提议细化 ADR 0018 的执行底座选择，不表示已接入主程序。

## 背景与证据

用户引入 Pi 的目的，是复用 agent harness 的调度、生命周期与恢复，减少后台维护与链路复杂性；产品围绕会议而非 coding。上轮锁定 Pi 1.4.0 / Node 26.12.1 的 [隔离 fixture](../../services/records/prototypes/pi-meeting-fixture/README.md)通过 8 项断言，覆盖队列去重、工具并发策略、父子取消、版本缺失与 SQLite 检查点恢复。没有验证真实供应商、MCP、Skill 安装器、主程序授权或全局资源调度。

## 提议

在既有 Record 后端内增加会议任务模块，使用 `@earendil-works/pi-durable` 1.4.0，保持依赖锁与独立持久库。首条纵向链路是“选一场会议 → 内置会后复盘 → 带引用的独立分析”。不启动编码 CLI，不引入第二份 Node，不替换原有录音与纪要链路。

| 所有者 | 负责内容 |
| --- | --- |
| Records 领域 | 账户/会议权限、所选材料版本、片段引用、人工稿与独立分析、删除/撤权 |
| 扩展目录 | 包内容与来源摘要、Skill/插件与配置版本、兼容性、启停、占用及清理 |
| 会议任务模块 | 把鉴权后的请求提交给 Durable；任务状态投影、全局 admission、截止时间、重开前检查 |
| Pi Durable | conversation/task、inbox、执行与子任务图、协作式取消、持久检查点及恢复 |
| 插件执行宿主 | 受控工具/MCP 调用、凭据、I/O 限额、进程生命周期与在途调用收束 |

这五项是逻辑模块，不是五个微服务。优先复用现有 worker、供应商客户端、日志脱敏与 Record 鉴权。会议任务模块对调用者的接口保持 `submit(request)`、`inspect(taskId, cursor)`、`cancel(taskId)` 三项；内部隐藏 Pi 任务与会话句柄、存储、恢复和状态映射。扩展安装管理不通过这个接口绕过自己的内容校验。

任务请求固定拥有者、具体会议 ID、纪要/转录/片段版本、材料范围、Skill 版本、插件代码/配置摘要、模型配置版本、预算、requestId。模型只能看显式提供的领域工具；Skill 文本不能改变工具授权。最小读取工具只返回所选快照，结果保存单独走幂等的分析产物入口。

“冻结”指内容与版本，不是冻结永久访问权。工具调用、恢复及结果读取重新鉴权；来源删除/权限撤回立即阻断，关闭 Skill 仅阻止新任务。任意文件、编码工具、直接 DB 或任意网络均不向模型开放。

## 状态、恢复与重复执行

产品状态由 Durable 执行态与宿主原因投影，不把每个 Pi 内部 phase 暴露给前端：排队、运行、等待处理、取消中、已取消、已完成、失败。原始状态和安全的原因码保存在后端便于诊断。SSE 使用可补历史的业务 cursor，不把临时模型 token 当持久确认。

Durable 存储与 Records 不是同一个事务。分析产物以 taskId/产物键幂等写入，成功结果可被恢复后核对；不能把工具调用与任务检查点包装成虚假的跨库原子提交。首期仅允许读取与独立分析保存，后续外部副作用必须另行设计执行授权、幂等、回执与核对流程。

应用重开负责打开存储、安装精确版本定义、检查未完成任务，再调用 Durable 恢复。缺旧版本显示等待；任务固定命名及保留旧定义由产品目录承担，Pi 不自动下载历史插件。协作式超时由宿主计时后发起取消；不合作代码需进程级终止与显式失败，普通进程不能宣称为安全沙箱。

会后与定时规则只形成可去重的任务请求，不另写模型执行循环。全局并发、录音优先、成本上限、离线待确认属于宿主策略，独立于 Pi 单轮工具并发。

## 取舍与后果

- 选择 Durable 可减少自建 inbox、任务图与检查点逻辑；仍需维护会议权限、Skill 适配及插件目录，不能承诺后台复杂性全部消失。
- 不同时引入 coding-agent SDK，减少重叠 session/resource 生命周期。Skill 首期支持受限文本子集；不承诺 coding-agent extension 格式直接可用。
- Durable 仍为 Experimental。固定精确版本、隔离库 schema、可关闭的新入口；每次升级执行故障与恢复回归。
- 三条依赖闭包体积测量见 [研究](../research/pi-harness-extension-feasibility-2026-10-31.md)。这不是完整安装包增量测量，不能据此宣称最终 DMG 体积或性能。

分期、可评审截图、接口落点、验收与回退见 [设计方案](../design/extension-center-2026-10-31.md)。当前仍待用户确认页面与能力范围后实施第一条产品链路。
