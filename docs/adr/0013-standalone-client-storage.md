# ADR 0013：独立客户端后台与本机存储压缩

状态：**proposed**。日期：2026-10-13。

用户已要求客户端不依赖 Web 开发后台，并继续完成 Apple Silicon 安装包。本轮按该范围实现独立后台及无损存储压缩；本文保留 proposed 状态，记录当前实现、取舍与后续验收边界，不将长期架构扩展视为已批准。

## 需要解决的问题

旧 Alpha 将界面和原生采集打包，却依赖本机开发 Record API 与 worker。关闭开发服务后，登录、历史读取、转录与纪要失去后台；开发账户、配置和会议数据也与安装版混用。随着转录、事件和纪要历史增长，全量 JSON 聚合的重复写入与 PCM 原音会增加本机空间和 I/O。

本轮目标是让安装版拥有自己的后台、账户、配置和持久数据，保留现有 Record 协议与可恢复补传，并减少可压缩内容的存储量。独立后台不意味着本地 ASR/LLM；云端供应商仍需网络与独立配置。

## 当前实现

- 原生应用持有内置 Node 子进程的生命周期。后台只监听回环地址并运行 Record API 与有界 worker；原生代理注入私有本机会话。退出通过父子进程通道关闭后台，重开时恢复中断任务租约。
- Apple Silicon 资源固定为 Node 24.21.0、SQLite 3.53.4，下载包通过固定 SHA-256 校验。正式包不读取开发 `.env`、旧外部 API 地址、开发数据或供应商密钥。
- 本机数据归属 `com.tts.meeting/backend/`；独立后台使用稳定的 WebView profile，与旧外部后台 profile 分开。旧数据保留，不自动迁移。
- SQLite 是 Record、转录、纪要与任务状态的写入权威，使用 WAL、FULL 同步和单一后台连接。调度元数据保持可查询，大段 JSON 压缩负载与相关投影在同一事务提交；无变化的聚合跳过重写。
- 音频以原始 PCM 的 SHA-256 寻址。带原始长度与哈希的无损 deflate 对象经临时文件写入、同步和原子发布后，再提交领域状态与 ACK；压缩无收益时保留原始对象，读取兼容旧格式。解码验证失败会明确报错。
- WebView IndexedDB 继续提供最多 48 MiB 的待传缓冲；本地后台持久 ACK 后删除相应队列项。原音频标识、重传幂等、转录修订、历史游标与停止排空语义继续沿用。
- 自动本机账户只用于该数据目录。供应商配置通过客户端设置保存到 `providers.json`；目录 `0700`、配置 `0600`，密钥仍为明文。

## 选型与取舍

继续使用 **SQLite + 不可变音频文件**。单人本机记录需要事务、索引、查询和崩溃恢复，SQLite 与既有领域提交路径相容；音频独立保存便于按哈希校验与流式读取，避免把大量音频 BLOB 混入主数据库。Node 内置 SQLite 的具体版本已在打包前检查，避免仅依赖系统上的未知运行时。

本轮采用无损 deflate，保持 ASR 输入字节与音频哈希不变。Opus 等有损编码、FLAC 及自适应编码可作为后续实验，需要分别比较空间、CPU、端到端时延、识别与说话人质量；不能用合成基准直接批准替换原音。

DuckDB 更适合作为分析侧工具，LMDB/RocksDB 会增加关系索引和事务整合工作；当前没有足够证据支持替换 SQLite。详细版本依据与替代方案见[本地存储研究](../research/client-local-storage-2026-10-13.md)。

压缩仍需读写完整 JSON 聚合，没有消除长会议的线性序列化成本。文件与 SQLite 也不共享单个原子事务；顺序持久化保障 ACK，但崩溃后可能留下未引用音频对象，后续清理必须以引用核对和保留窗口为前提。压缩不提供加密，Keychain、自动备份、导入迁移及更细粒度的热数据表均不属于本轮已实现范围。

## 验收边界

本地验收应分别覆盖：压缩往返与损坏检测、旧对象读取、SQLite 事务回滚与重启、租约恢复、父进程退出后的后台关闭、正式包不访问外部开发 API，以及隔离数据目录中的独立启动。

合成 120 分钟 fixture 仅用于比较相同输入下的数据库空间与写入成本；它不能预测真实语音压缩率、两小时实体录音稳定性、供应商时延或模型质量。全新 Mac 首次授权、真实系统音频与麦克风、休眠恢复、长会话、正式签名与公证仍需单独验收。
