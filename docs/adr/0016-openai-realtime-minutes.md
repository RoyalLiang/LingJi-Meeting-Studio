# ADR 0016：可选的原音理解与并行转录留证

状态：proposed。用户已明确授权本轮本地实现与验证；正式发行、真实供应商采用和生产部署不在本轮授权范围。

日期：2026-10-22。

## 问题

原有会议纪要只消费转录文本。仅将文字模型端点替换为 OpenAI 地址，不能让 Agent 接收音频。直接移除 ASR 又会损失当前产品依赖的逐字稿、版本引用和原音定位。

此外，原有两小时配额累计所有音轨样本，双音轨可能在约一小时触发，与会议墙钟时长不一致。

## 本地实施选择

1. 保留默认 ASR＋LLM 链路，新增 `MINUTES_MODE=openai-realtime` 和独立后端配置。
2. 先持久化原音，再由独立 Realtime lane 读取已确认音频；ASR lane 并行推进，互不替代持久化确认或状态。
3. Realtime 仅输出文字。正式纪要仍通过原有冻结转录快照、片段版本、generation/fence、人工编辑保护和结构校验。
4. 会话按五分钟轮换；短窗口按音轨和会议时间划分，恢复和终稿从本地原音按需重放，分层合并已校验结果。
5. 每场会议单独登记原音发送授权。已有 ASR 授权不自动升级；原音留存和分享继续独立。
6. 临时原音清理等待直接音频纪要所需工作结束，继续遵守既有 24 小时临时音频期限。
7. 去除录音累计样本和文件导入的两小时硬限制，保留容量、块数、请求和纪要预算保护。

## 取舍与待验

直接音频理解可能保留转录文本未表达的语音信息，但本轮没有真实会议对照，不能宣称纪要更准确、更便宜或更低延迟。正式发布引用仍依赖 ASR 确认；多音轨分别处理与合并会增加实际请求。

Realtime 不可用时明确显示错误，用户可主动改回旧方式。无自动跨模式回退，避免改变用户选择、发送范围和质量证据。

本地 HTTP/WebSocket、SQLite、合成时长和浏览器控件验证不能代替真实供应商、实体设备三小时录制或发行安装包验收。
