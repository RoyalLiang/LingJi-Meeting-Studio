# ADR 0017：纪要导入与技能引导发布共用发布计划

状态：proposed。提出于 2026-10-31，尚未批准实施。

## 先验证飞书导入，再扩展可安装技能

现有纪要已经带有人工修订、转录版本和引用快照；当前工作区只有 Markdown/WAV 导出及分享能力。要将纪要导入外部平台，需要确保预览内容就是实际发送内容，并保护本地和远端的人工编辑。

建议先实现飞书云文档的确定性导入，画板是文档内的可选纪要树组件。随后增加 Agent Skills 格式的安装与读取，以及受支持的 MCP 连接。内置导入与技能引导共用发布草稿、目标位置、内容快照、确认与回执，避免每个技能各自实现外发权限。

这是一项待评审提议，本轮只增加独立原型与研究文档。用户已明确画板属于云文档组件；产品界面不设置独立的“画板”发布分类。

## 让宿主拥有执行权限

- Skill 提供整理方法与步骤；宿主按需加载 `SKILL.md` 及引用资料。安装不能自动获得文件、命令或外发权限。
- 浏览器首版由后端管理飞书 OAuth、凭据和远程 MCP；本地 stdio 需要后续桌面宿主或桥接。首版不执行技能包中的脚本。
- 飞书导入由内置 API 适配器完成；MCP 的可写能力以实际协商得到的工具为准，不假设官方 MCP 覆盖全部文档和画板操作。
- 用户确认前，发布计划必须绑定记录、纪要修订、转录修订、引用快照、人工笔记修订、内容摘要、接收位置和写入范围。任何一项变化都使旧确认失效。
- 发布完成保存外部资源 ID、URL、内容摘要和执行阶段。断线先核对回执再恢复，不能盲目重建文档或整棵树。
- 首次只创建独立导入副本；更新远端内容需比对版本。原音、完整转录、群消息和任务创建均不由“安装技能”或“导入纪要”隐含授权。

## 验证后才能承诺真实效果

需要真实飞书租户确认应用可用范围、用户与资源权限、原生树布局和折叠、表格和引用转换、超限拆批与部分失败恢复。需要真实 MCP 确认工具范围、认证与返回结果。
