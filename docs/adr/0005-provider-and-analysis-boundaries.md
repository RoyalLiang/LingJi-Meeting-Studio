# ADR 0005：服务配置与意图分析边界

状态：proposed；已在用户授权的本地工程改造中实现对应切片，生产采用仍待验收。日期：2026-10-12。

## 问题

旧豆包配置没有进入新的 Record 运行路径，设置页只显示状态，无法修正地址；语音凭据和纪要模型凭据容易混淆。直接对所有历史转录自动调用模型还会扩大数据发送范围。页面默认浏览器控件和外层滚动也影响会议中的稳定操作。

## 当前实现

- `Provider Configuration` 模块集中处理默认值、旧变量别名、地址补全、脱敏读取、权限和原子保存。默认豆包 v3，旧 AST 作为独立适配器；密钥只留在服务端，不能由浏览器读取。
- ASR 适配器只在最终响应后提交。Record worker 保持同来源顺序，两个来源可以并行；部分响应不能冒充持久转录。失败继续遵守重试上限、租约和停止排空语义。
- `Intent Insight` 与纪要都引用片段和转录版本。默认规则提示；逐记录点击模型分析后才允许该记录的模型意图任务。旧结果不能覆盖新版本，模型失败不撤销已经保存的转录。
- 本地提取与模型纪要分别标注。前者按规则组织原文，后者由用户显式发起，输入转录快照和笔记。所有行动仍为候选，不自动外发。
- Web 层以 Select、DeviceSettings、ProviderSettings、Insights、AudioPlayer 和 MinutesPanel 组件隔离交互；页面框架固定居中，内容区与纪要分别滚动。

## 取舍与验证门

本地覆盖文件适用于单机试点；多实例配置、密钥托管及轮换仍需独立设计。两秒短批次便于持久恢复，但可能损失跨批次语义。规则意图的准确率、模型判断的事实性不能由 JSON 或引用格式校验证明。

真实豆包只验证了约六秒合成语音。当前 HTTP 模型配置被保留，代理的真实调用测试被自动审批拒绝；因此模型适配器 fixture 不升级为真实模型验收。详见[验收表](../engineering/acceptance.md)。
