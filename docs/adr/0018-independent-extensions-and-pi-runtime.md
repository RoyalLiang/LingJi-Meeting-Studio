# ADR 0018：独立会议扩展与可选 Pi 执行引擎

状态：**proposed**。2026-10-31。产品方向已由用户明确，下面的实现方式尚未批准或接入。

## 当前方向

用户要求暂停 Skill/自定义导出，保留飞书云文档导出（画板属于文档组件），同时保留并设计 Skill 或插件能力，并评估 pi harness。

因此，Markdown 与飞书云文档使用固定导出流程；扩展中心与会议助手独立。ADR 0017 中将 Skill 作为导出入口、通过聊天确认发布的提议暂停，历史记录只用于追溯。

## 让会议数据、扩展与执行各自保有所有权

这些是现有后端内的逻辑模块，当前不建议拆成新的微服务：

| 模块 | 拥有的内容 | 不承担的职责 |
| --- | --- | --- |
| Records | 账户隔离、会议、纪要/转录修订、引用快照、人工稿 | 不把模型输出直接当作领域写入 |
| 固定导出器 | Markdown 内容转换、飞书 OAuth/资源写入、导出计划与回执 | 不加载 Skill 或调用通用 agent loop |
| 扩展目录 | Skill/插件来源、版本、内容摘要、启停状态与兼容性 | 安装状态不自动转化为运行权限 |
| 会议助手 | 绑定 Skill 版本和选定会议快照的流式会话、独立结果与取消状态 | 首阶段不改写纪要、不导出、不访问其他会议 |
| 工具执行模块 | 检查身份、会议范围、修订、参数与能力白名单，再调用已注册工具 | 不让模型或插件自行扩大授权 |
| 可选运行时 | 模型流、agent loop、工具调用事件与取消 | 不拥有 Records、飞书凭据或最终写入权限 |

宿主向运行时提供已经限制好的会议快照与工具集合；运行时不能直接收到数据库连接、应用目录或任意文件/命令能力。当前只用一个执行方式时，先保持直接调用；只有确实需要替换两种执行方式，再落正式 Adapter，避免为尚未接入的 Pi 建空包装。

## 区分四类扩展

- **Skill**：处理方法、模板与参考知识，例如复盘、风险梳理、术语解释。首批支持无脚本指引包，按需加载。
- **插件/原生工具**：程序能力，例如读取选定会议、选定资料检索或专用 UI。代码插件在宿主执行的信任和生命周期不同于文本 Skill，不能共用一个“安装即授权”按钮。
- **MCP 连接**：工具/资源协议的接入方式，可作为插件工具的实现；真实能力以服务协商结果为准。
- **Harness**：执行循环、会话与事件组织，不是权限系统，也不是业务数据的所有者。

扩展中心分 Skills 与插件/连接两栏。Skill 可以独立启停和使用；插件分别展示能力范围、连接状态和是否已验证。飞书连接只服务固定导出，助手不会因启用 Skill 而获得它的写入工具。

## Pi 接入取舍

当前建议：先完成固定导出和独立扩展目录设计。固定的问答或分析可以复用现有模型调用；需要多轮领域工具调度时，进行 `pi-agent-core` 的隔离 spike。完整 `pi-coding-agent` harness 暂不作为默认产品依赖。

理由与固定版本证据见 [Pi 一手研究](../research/pi-harness-extension-feasibility-2026-10-31.md)：core 默认工具为空；完整 SDK 的默认工具、资源发现、文件设置和持久会话带来额外所有权。现有终端 Node v22.14.0 也未达到本次 Pi 1.4.0 声明的 Node ≥22.19。不能把同进程或普通子进程误作权限隔离。

复用现有后端模型配置不等于已兼容 Pi 的模型与工具协议，还需明确配置映射或自定义流接口；凭据不放入前端或 Skill。

未来 spike 只做一条“所选会议问答”：在独立运行环境中，显式注册读取当前纪要、读取引用片段等领域只读工具；从一场合成会议验证流式、取消、工具范围和引用。模型、上下文与输出结果继续由聆记管理。

退出条件：

1. 不加载全局 Skill、配置、任意目录资源或默认文件/命令工具。
2. 工具无法跨账户、跨会议或绕过绑定修订；拒绝未注册工具，记录/人工纪要前后摘要不变。
3. 停止生成不会覆盖已有结果；引用仍能定位到冻结片段修订；工具失败有可恢复的明确状态。
4. 对同一输入比较现有实现与 core，确认引入依赖确实减少维护工作，再决定是否正式接入。
5. 如以后考虑完整 harness、代码插件或本地 stdio，另行明确资源发现、持久化、进程与网络访问条件。本轮不执行这一步。

## 证据层级

本轮仅更新独立 HTML 原型、文档与截图；没有安装 Pi、加载外部插件、调用真实模型或执行外发。原型中的启停与权限检查只验证交互，不证明真实运行时隔离。当前预览见[方向与界面](../design/minutes-publishing-preview-2026-10-30.md)。
