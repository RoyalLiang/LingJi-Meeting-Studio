# ADR 0004：Record 垂直切片与有界持久处理

状态：proposed；本轮已形成工程实现，生产采用仍待环境验收。日期：2026-10-11。

用户已授权按路线图实施全部阶段，浏览器优先、免安装、组件化领域建模；视觉已确认采用磨砂材质和按需纪要侧栏。

选择新增 `packages/records` 与 `services/records` 作为一致的 Record Commit 模块，保留旧原型兼容入口。HTTP 和 worker 都调用同一领域模型，通过聚合事务串行提交内容和事件。Record 包含可中断 Session，每个 Source 使用独立 epoch；音频身份同时校验 session、source、序号、摘要和采样时间。

Web 使用 React/TypeScript/Vite；UI 原语、转录、笔记、纪要、采集与补传分离。用户手势先获取来源，2 秒 PCM 先落 IndexedDB，再请求 durable ACK。视图以服务端状态为准，事件断线后按持久游标补历史，过期取完整快照。

本地默认 SQLite FULL/WAL + fsync 音频；生产适配 Postgres JSONB 行锁和私有 S3 条件写。聚合内的有界持久日志同时提交，不引入完整事件溯源和独立消息中间件。任务按 nextWorkAt 索引、有界并发、租约与 fence 处理。数据有记录/时长/快照预算。

识别首版选择可重放的短批次 HTTP，降低跨进程流状态恢复复杂度。代价是缺少流式 partial、上下文不足和潜在片段边界损失；必须真实测量后决定复用旧流式供应商并增加 provider drain。不能把短批次标作供应商流式识别。

纪要固定快照、引用 schema、人工版本保护，保存当前与有限历史。分享默认纪要及实际引用的快照，不能连带泄露未引用的全量转录。外部动作仅提供可审阅文件，仓库与独立授权到位后才启用外发。

后续触发：聚合大小/锁等待/查询负担经测量超出目标时拆分 chunk、事件与 job 表；真实识别显示边界损失时增加流式/上下文适配；跨记录问题集证明价值时再增加向量或图检索。先完成 [验收门](../engineering/acceptance.md)，不以新增中间件代替验证。
