# 会中纪要、主题与流式协议

更新：2026-10-14。本文区分已实现行为、验证证据和后续建议。[飞书调研](../research/feishu-minutes-analysis-2026-10-12.md)提供产品参考，不代表获知飞书内部实现。

## 使用方式与延迟

设置中选择 **Chat Completions** 或 **Responses**，填写服务方提供的完整接口地址，保存后生效。地址按原值使用，路径、查询参数和尾斜杠不会被补全或替换；切换协议只改变请求体。不会探测并静默切换协议。两种协议用于纪要、模型意图识别和翻译；Responses 显式设置 `store:false`，不能据此保证第三方服务不保留数据。

新建记录时，模型已配置会预选“自动生成 AI 纪要”，并在创建前显示转录与笔记的云端使用说明。已有记录默认关闭，在纪要侧栏启用。关闭会取消本记录尚未完成的自动任务并隔离迟到结果。自动纪要不等同于授权模型意图识别或翻译；两者仍有独立入口。

无需用户编写提示词。内置系统提示要求中文结构化 JSON、连续主题、原文版本引用、不编造决定/负责人/日期、不根据输入来源推断真实身份，并把转录和笔记视为资料。三个模板可用于显式重新整理；自动任务当前采用会议模板。提示词不能取代输出结构与引用校验。

会中默认每 **30 秒**检查是否有新转录，可选 15、30、60、120 秒。同一记录最多一个自动生成任务；模型较慢时不会叠加自动请求。停止录音后，必须先补齐音频并完成 ASR 排空，再立即排队终稿。失败会明确显示。终稿仅对暂时性超时、连接中断、限流与服务端5xx有限重试，等待15秒、30秒，总计最多3次；配置、结构、引用和硬容量错误不自动重试，修复后可手动重新整理。

实际等待时间为：

`音频片段积累 + ASR + 自动刷新剩余间隔 + 队列等待 + 模型首字 + 浏览器事件更新`

其中刷新间隔不是端到端 SLA。worker 的 ASR 轮询间隔为 250 ms，模型任务分别轮询；浏览器 SSE 服务每 250 ms 读取新事件。页面展示从请求开始计算的模型首字和完整响应耗时，尚未建立完整音频到纪要 P50/P95 指标。

本地虚构 Responses 服务浏览器联调约 11.7 秒完成，输出前半段已在页面出现；它是人为节流的协议验证，不能代表当前配置模型的实际速度。真实 HTTP 模型调用未完成，受此前自动审批拒绝明文发送密钥的限制。

## 模块和一致性

- `services/records/src/llm.mjs` 统一两种协议的 JSON 与 SSE，处理 UTF-8 跨块、结束事件、长度限制和错误；截断流即使已有可解析 JSON，也不能发布为正式结果。
- `packages/records/src/automation.mjs` 负责启用、间隔、去重、会中/终稿调度和受控预览。
- `worker.mjs` 的 audio、minutes、intents、translation 使用独立轮询链。翻译等待不再阻塞转录持久化。各任务仍依靠租约、版本与 fence 防止并发重复写入。
- `liveMinutes` 累计保留已校验的会中结果，与有正式版本号的 `minutes` 分开。首轮覆盖可用转录，后续只处理新增片段与前面两个片段，并携带有稳定主题 ID 的项目上下文。已校验窗口可先显示为“正在更新”的草稿。追加转录不使会中结果失效；修改当前窗口或已累计的旧引用会隔离在途结果。终稿仍要求整个转录版本一致。
- 人工编辑后，自动纪要暂停覆盖。笔记版本、纪要版本、删除 generation 和任务 fence 变化都阻止旧任务提交。
- 流式预览只显示 JSON 中的可见标题和文本，未校验引用不能用于编辑、分享或导出。完整结果通过引用校验后才成为有效草稿或正式版本。

事件 `minutes.delta` 携带 jobId；浏览器以同一记录的 GET 读取持久化预览。约 200 ms 合并一次模型增量，避免每个 token 写数据库。断线后由 SSE cursor/reset 补历史，再读取最新聚合。当前是供应商 SSE 到持久事件到浏览器 SSE 的链路，并非浏览器直接持有供应商密钥。

## 主题、说话人与图表

模型返回 `topics:[{title,summary,evidence:[{segmentId,revision}]}]`。转录按原有时间顺序显示，不因主题重排；连续同主题片段共享摘要标题与背景。修改过而未重新归纳的片段不沿用失效主题。主题颜色还配有文字标题，颜色不是唯一标识。侧栏提供主题树，以及依据有时间戳的引用片段计算的覆盖时长横条；纯文本导入没有虚构时间，也没有时长横条。

当前支持手工标注说话人和独立音频来源。麦克风、共享音轨不是不同真实说话人的可靠证据，页面明确显示“来源 · 未标注说话人”。当前短批次 ASR 没有完成单音轨多人分离，也没有声纹身份系统。

后续建议：先以长窗口 ASR/diarization 输出匿名 speakerId，维持跨窗口聚类与置信度，再由用户纠正名称；声纹匹配必须额外授权和保留期限。不能让文本模型猜测人的身份。时间轴、流程图和表格可扩展为受限结构；饼图、漏斗图只接受带单位和原文证据的明确数值。不要用主题数量充当业务比例，也不要执行模型生成的任意 HTML/脚本。

## 验证边界

Node 回归验证 Responses/Chat 的真实本地 SSE、提前增量、UTF-8 分块、截断拒绝、自动调度、修改/取消保护、主题引用与 ASR 并行。浏览器使用隔离数据目录、虚构密钥和 localhost 上游，确认自动重生成、流式文本、主题背景、主题树、自定义协议选择和手机布局。它不证明真实模型质量、多人识别、长会话、Postgres、多机任务或生产部署。

协议依据：[Responses 创建接口](https://developers.openai.com/api/reference/resources/responses/methods/create)、[流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)。
