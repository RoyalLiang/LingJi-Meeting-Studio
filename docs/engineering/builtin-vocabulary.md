# 使用内置词表辅助转录、纪要与意图识别

内置词表随安装包提供。应用根据会议标题、备注、最近发言或助手请求选择少量相关词，用作热词、拼写参考和转录纠错候选。个人词表仍独立保存，重复词以个人设置为准。

设置的「转录词表」保留两个个人补充词编辑框，不会把整份内置词表复制进账号数据。内置资源的版本和加载状态保留在诊断接口及构建清单中。

当前，整理词表分为人名、项目名、进度、常见词和专有名词。总词表用于查看、按类复核和检索，内置识别层采用更严格的筛选；分类结果不等于新增了五类在线检索服务。进度表达作为语义候选保留，不根据词表推断实际项目进度；低频项目别名先复核，普通进度词不全部加入强热词。

当前，纪要也按会议标题、笔记、当前转录和分段摘要检索术语。个人明确别名优先，文本纪要、豆包音频纪要和 Realtime 共用同一拼写参考；标题、小结、正文、行动和重点速览保持一致。已保存纪要需重新整理才使用新参考，不自动覆盖人工内容。

## 控制词表带来的偏置

- 先匹配完整词和符合边界的缩写，再检索有限数量的相近中文词。
- 只有精确出现的业务词可以召回语料中共现的业务词，最多补充 12 条。共现关系不表示同义关系、系统事实或人员归属。
- 人名只按明确提及召回，最多 8 条；不根据共现或相近字自动猜人名。
- 常见英语小写词不会激活同形的大写代码；拉丁名字不能在其他拉丁单词内部命中。
- ASR 继续遵守各供应商的热词预算。纪要与意图参考最多 48 词、约 1,000 字符，原输入接近预算时省略词表。
- 模糊检索限制为 128 个候选、每候选 64 个位置窗口，避免逐词扫描整份上下文。

词表不会直接改写转录、数字、否定、条件或人工编辑。转录修订沿用现有候选确认、版本检查和原识别文本保留机制。会议意图仍须引用原片段及版本；助手仍受已选 Skill、MCP 与工具权限约束。

## 区分引擎支持范围

Deepgram、OpenAI 兼容 ASR 及支持该参数的豆包 ASR 路径消费热词配置，实际效果需用真实音频验证。

当前 SenseVoice 本地引擎、外部 FunASR、豆包音频直接理解及 Realtime 路径没有接入这份热词参数。本地转录仍可使用后续的词表纠错候选；这不等于本地模型已经支持原生热词。

豆包音频和 Realtime 的纪要请求可以携带上述文字拼写参考，这与 ASR 引擎原生热词参数是不同的能力。参考命中不能证明模型准确率已经提升，仍需真实音频评测。

## 把词表加入安装包

词条正文位于 Git 忽略的 `services/records/src/data/builtin-vocabulary.private.json`。Git 只保存加载与构建代码，以及同目录的 `builtin-vocabulary.manifest.json`（版本、条数、字节数、SHA-256）。原始 Jira、完整来源标注和待复核词不会打入应用。

私有构建输入为 UTF-8 JSON 经 gzip 压缩后的 base64，按原顺序存入对应词表版本的两段仓库 Secret，由工作流传入环境变量 `TTS_BUILTIN_VOCABULARY_GZIP_BASE64_PART1`、`TTS_BUILTIN_VOCABULARY_GZIP_BASE64_PART2`。每段不超过 30,000 字符，独立保存以保证日志遮罩生效；物化脚本直接拼接后解码。Windows 单个环境变量上限为 32,767 字符，见[微软说明](https://learn.microsoft.com/en-us/windows/win32/procthread/environment-variables)。当前两段覆盖本版输入；超过 60,000 字符时需扩充分段或改用受控文件输入，不能截断。不要把正文放到 workflow 输入、日志或提交中。已获得对应输入的本地环境可以运行：

```sh
node scripts/materialize-builtin-vocabulary.mjs
```

脚本核对摘要、版本、条数、唯一性和字段约束，只输出元数据。三个桌面构建任务先物化资源，再检查它确实受 Git 忽略。冻结构建读取所选源码版本里的公开清单，校验并单独复制私有词表到构建目录；词条不进入源文件清单或源码归档。缺失或摘要不符会中止构建；`prepare-client-backend.mjs` 还会核对复制后的资源摘要，并在运行时清单中记录词表版本。

原始构建输入保留私有权限，安装资源以普通应用用户可读的权限打包；安装后的后台烟测会通过账号接口确认词表已加载。安装包中包含可读取的词表资源；不进入 Git 不表示安装包内的词条经过保密加密。运行时不需要仓库 Secret，也不读取 Jira。

本版工作流从所选源码 SHA 的清单读取词表版本，再选择对应 Secret 映射到物化环境变量：`20261105.2` 使用保留的原输入，`20261105.3` 使用 `TTS_BUILTIN_VOCABULARY_20261105_3_PART1` / `PART2`。手动重建含旧版资源的标签时也依照所选源码，而非当前 main 的词表。未登记的版本在 verify 阶段拒绝，新增版本须显式配置匹配输入。

## 更新、回滚和验证

更新时同时准备匹配的私有资源、公开清单和构建 Secret。旧版本重建也需要其对应资源，摘要不匹配时不会自动套用新词表。私有来源与处理记录保留在授权的本地资料目录，不放进源码历史。

本轮复用已有的 37,917 条 Jira 六字段标题快照，按明确 UTC 一天窗口补充91条（90条已有记录、一条新增），合计37,918条唯一Jira；另保留三份有版本的方案/需求资料。近期补充带状态等附加字段，未刷新全部工单的当前状态。标题词频、完整搭配、词边界、上下文共现和来源核对用于筛选；自动标注不等于人工金标。资料不包含工单正文、评论和附件全量，也不是跨分区的同一原子快照。

语料内的词组命中率只能说明覆盖范围。真实音频 CER/WER、专名准确率、错误纠偏率、会议意图和助手任务成功率仍需独立评测。

v0.2.40 的 Jira 词表刷新和使用边界见本轮证据。人工校对按所检查的最近 120 段、每 20 段一个窗口检索并合并参考词，避免末尾话题覆盖早期片段；合并后仍限制内置词数、字符数和人名数。生成候选与确认接口共用同一词表指纹范围，保留转录修订和人工确认校验。

内置词可标记为 `match: exact`：仍可作为原文中精确出现的参考，但不参与模糊召回、关联扩展、同音候选或改变原文事实的模型替换。进度、状态及歧义常用词使用这一策略；新条目未声明时沿用原有上下文匹配策略。它不会给本地 SenseVoice 增加热词解码能力。

内置词已定义匹配策略时，通用词表不从回退路径重新引入被检索预算排除的同名词，避免丢失精确参考约束。
