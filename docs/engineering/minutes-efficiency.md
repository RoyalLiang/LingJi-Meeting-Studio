# 纪要输入、输出与服务地址

v0.1.36 使用请求内整数索引传输转录引用，来源、说话人和历史纠错目标采用短别名。模型返回后先还原原始 ID 和 revision，再进行原有引用、修订和事实校验；数据库和导出不保存临时索引。转录正文、笔记、时间、说话人名称及历史条件不因压缩被截断。

文字模型的分窗上界由 2 分钟调整为 5 分钟，仍受原有字节预算约束；音频模型保持 2 分钟限制。自动纪要仍按设置的间隔提交增量，不等待满 5 分钟。跨窗口的语义汇总保留，尤其用于识别本批前后发言中的撤回、否定与更正。所有原文进入叶窗口，汇总保留各窗口摘要和受预算约束的原文摘录；服务端仍依据完整冻结原文校验。

文字汇总按实际压缩载荷计算预算，避免重复 UUID 元数据先占满预算；不扩大原有输入上限。`RECORD_MINUTES_INPUT_BYTES` 默认 24000，`RECORD_MINUTES_SYNTHESIS_INPUT_BYTES` 默认 96000，均为业务载荷的字节预算，另有系统指令和协议包装，不等于 token 数或模型上下文上限。

## 服务地址

| 设置 | 实际请求 |
| --- | --- |
| `https://gateway.example/v1`，Responses | `https://gateway.example/v1/responses` |
| `https://gateway.example/v1`，Chat Completions | `https://gateway.example/v1/chat/completions` |
| 完整接口、自定义根地址、带查询参数的 URL | 保持原地址 |

仅明确且不带查询参数的根级 `/vN` 基址自动补协议路径，已有完整路径不会重复追加。带查询参数的自定义服务仍应填写完整请求地址。旧版直接 POST 配置地址，因此把 `/v1` 当完整接口时可能得到 404；这与模型名不存在、密钥失败是不同问题。可保存后使用“测试纪要”验证。

## 怎样看用量

输入、输出和总量来自供应商实际返回。缓存输入是输入的子集，推理输出是输出的子集，均已计入原总量，不再相加。仅在供应商提供这些数值时显示明细；没有提供就保持未知。缓存命中可影响实际计费，但不会使面板中的输入 token 自动消失，实际收费仍以服务方为准。

本轮保留用户选择的推理强度，不把“自动”强制改成“低”，也不以很小的输出上限截断 JSON。一次虚构短会议中低强度并未必更省，不能将它概括为通用规律。

## 复现实验

在具有本地 `v0.1.35` 标签的源码 checkout 中运行：

```sh
node scripts/benchmark-minutes-efficiency.mjs
```

脚本使用纯合成的 50 分钟、300 片段，不启动模型或发送网络请求。它对比引用序列化、分窗和保留全部 300 条事实的桩流程；旧流程可能在未压缩元数据预算处失败。输出标明 `providerTokensMeasured: false`，字节量和桩调用次数不能替代真实会议的 token、耗时或质量验收。
