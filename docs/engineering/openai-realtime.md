# 使用 OpenAI Realtime 直接理解会议音频

更新：2026-10-22。以下是本地源码实现，尚未打包或发布。真实 OpenAI 服务、真实会议质量和实体设备长录制尚未验证。

## 在设置中选择纪要输入方式

打开 **设置与诊断 → 纪要输入方式 → 会议理解**。

- **ASR＋LLM · 转录后整理**：默认方式，保留原有转录后生成纪要的链路。
- **OpenAI Realtime · 音频直接理解**：原音进入 Realtime 会话，ASR 独立生成转录；发布纪要时仍校验转录片段 ID 和版本。

Realtime 需要独立的 WebSocket 地址、模型和密钥。OpenAI 官方地址为 `wss://api.openai.com/v1/realtime`，模型示例为 `gpt-realtime-2.1`，账户是否可用需要实际验证。第三方兼容 Chat Completions 或 Responses 不代表支持 Realtime。[OpenAI 连接文档](https://developers.openai.com/api/docs/guides/voice-websockets?voice-api=realtime)

保存后再使用 **测试纪要**。Realtime 模式的连接测试发送合成静音和虚构指令，不读取会议。测试服务可达不能证明真实语音理解质量。

也可在服务端配置：

```dotenv
MINUTES_MODE=openai-realtime
OPENAI_REALTIME_URL=wss://api.openai.com/v1/realtime
OPENAI_REALTIME_MODEL=gpt-realtime-2.1
OPENAI_REALTIME_API_KEY=<服务端密钥>
```

设置页保存的配置优先于环境变量。密钥不放入 `VITE_*`，读取设置时仅返回“已设置”。

## 保留转录服务和文字模型配置

ASR 继续独立工作，保存逐字稿、说话人和原音定位所需的片段信息。Realtime 接收已持久化的 PCM 音频，不依赖 ASR 先返回文字；正式纪要仍等待可引用的确认转录，不承诺绕过转录后立即发布带引用的结果。

原有 `LLM_PROTOCOL`、`LLM_API_URL`、`LLM_MODEL`、`LLM_API_KEY` 继续服务于旧纪要方式和独立文字分析。跨会议洞察和模型意图分析不会把 Realtime 配置误当成已配置文字模型。专用翻译配置保持独立。

## 为每场会议明确选择原音发送

Realtime 模式下，快速记录先打开新建表单。**自动生成 AI 纪要**默认不勾选，文案说明本场音频将直接发送至 Realtime。勾选并创建才登记本场原音发送授权。

旧会议的转录授权不会自动升级为 Realtime 原音授权。可在本场 **整理设置** 中明确开启；手动生成也会显示发送范围。屏幕共享授权、原音留存和外部分享继续独立处理。

关闭自动整理后，后台接收通道会关闭。人工修订、转录版本变化、删除和任务取消继续通过既有 generation/fence/版本检查隔离迟到结果。模型只生成纪要和行动候选，不外发行动。

## 从本地音频恢复连接

后端保留 Record/Session/Source/epoch/sequence、哈希和偏移的持久化确认语义。Realtime 的输入确认不会替代本地 ACK，也不会修改 ASR 音频块状态。

原有 16kHz PCM16 在发送时转换为 24kHz，原始存储不改写。应用使用显式提交划分音频项，关闭供应商自动回话，只请求文字结果；应用提供的音频映射与真实片段版本一起约束输出。[OpenAI 会话与响应文档](https://developers.openai.com/api/docs/guides/realtime-conversations)

共享会话在五分钟墙钟时间或累计五分钟音轨输入后轮换，恢复时仅补入最近两分钟上下文。每个会话串行执行提交和响应；独立音轨与超过两分钟的长转录片段分窗，终稿按已校验窗口分层合并。终稿缺少当前会话中的音频时，从持久化原音重新加载对应窗口。

断线、超时、缺失原音、非法 JSON 和失效引用都明确失败，不会静默切换回文字纪要或模拟结果。失败的音频接收通道按五秒退避恢复；纪要任务沿用既有重试与版本隔离机制。实际返回的用量才计入统计，包括已返回用量的失败响应。

**不保留原音**仍允许处理期间临时保存。ASR 完成后，待完成的 Realtime 终稿和重试仍需要音频；成功终稿完成后允许清理。原有临时音频 24 小时过期策略继续生效，超过期限的失败任务可能无法再读取原音。已经清理的历史原音不会恢复，也不会偷偷回退到文字模型。

## 录音不再受两小时累计配额限制

后端移除了 `16000 × 60 × 120` 累计样本配额，因此双音轨不会约一小时就耗尽；文件导入也移除了两小时时长检查。Bootstrap 返回 `maxMinutes: null`，界面不再显示两小时上限。

资源保护仍保留：待传队列 48 MiB、单文件导入 64 MiB、单块音频最多 15 秒、单记录最多 200,000 块、每来源 sequence 小于 1,000,000，以及既有纪要输入预算和最多 512 个窗口。长文件仍需要浏览器解码内存，网页关闭、系统休眠和设备权限仍会影响采集。解除两小时限制不代表无限容量或任意时长的实体录制已经验收。
