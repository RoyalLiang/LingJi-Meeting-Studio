# 录音保存、转录与纪要分别查看进度

会议页分别显示原音、已保存、最新转录和纪要依据。原音时长包含本机队列里的实际 PCM；已保存表示记录服务确认持久化的音频。最新转录和纪要依据是最近片段的位置，不表示中间所有音频已处理或事实完整召回。

## 网络或服务暂时不可用时保留录音

本机队列原始 PCM 预算从 48 MiB 调整为最高 512 MiB，同时根据浏览器存储配额保留余量。预算是所有会议共享的，不会在新建会议时清空旧录音。新采集先检查容量；真正不足时提示尚未开始录音。采集中存储失败时立即显示错误，不等待停止排空结束；未确认音频继续保留和重试。达到上限后仍需先恢复补传或释放磁盘空间，不能无限离线录制。

音频按 record/source/epoch/sequence 标识。上传有 30 秒期限，失联后解除挂起并重试，重复上传由服务端幂等确认。不同音源最多两路并行，新增片段可唤醒空闲通道。下载原音不受该上传期限限制。短暂补传故障只在页面显示一个恢复提示，不反复弹全局错误。

原生采集先把 PCM 放入临时文件；WebView 成功写入 IndexedDB 后才通过 capture_ack 确认释放。写入失败时停止生产，保留未确认的头部与尾部并重试，停止操作会排空。**未确认的原生临时文件依赖当前应用进程存活，尚不是崩溃后可恢复的持久录音。此时请保持应用开启。** 已确认写入 IndexedDB 的数据可在重启后补传。导出本机待补传备份不会删除队列。

## 转录和纪要不应拖住采集

原音保存、异步转录和纪要任务已有各自确认与修订状态。本轮补上原生持久化确认、请求期限及诚实的采集时钟，并降低纪要草稿写放大：模型流读取不等待预览写入，同一时间只写一个预览，后续合并最新内容；最终提交等待在途预览收尾。

当前记录服务仍共享 Node 事件循环及记录聚合存储。同步写入仍可能延迟其他请求；本轮没有完成独立进程及独立存储重构。[后续架构建议](../adr/0022-capture-processing-isolation.md)为 proposed，不代表已经实现。

## 保持一份纪要与原有样式

纪要、逐字记录、笔记及翻译有各自的组件标识。连续刷新和后台同步不会因相同 key 错误复用而堆叠纪要。原有树形卡片、字号、圆角和配色保持不变；样式验证使用完整会话页。

## 发言归属与来源入口

纪要优先使用生成时冻结的发言标签；缺失时只从同片段同修订的转录及已有说话人注册信息补齐“说话人 1/2”。供应商没有提供可验证身份时显示“未区分说话人”，不会根据内容猜测。可在逐字记录标注后重新整理。卡片原有“原文 N”行已换为右上角来源图标，仍能打开引用快照。

## 更新与窗口

录制或未排空时继续阻止安装。下载后选择安装，会再次确认退出并安装；先停止本应用拥有的记录服务，再进行安装交接。macOS 校验 DMG 内身份、版本和签名，预备替换与备份；只有新应用完成就绪后才清理备份，启动失败保留备份供恢复。Windows 等待旧客户端退出后启动安装程序；Linux 交给系统 DEB 安装器。

首次从旧版本升级时，安装动作仍由旧程序执行，请先结束录音、完成补传并完全退出旧客户端，再安装本版。三平台真实升级仍需设备验收。

主窗口最小化或关闭后可重复进入悬浮录音窗；恢复主窗口后仍可再次收起。暂停且有待保存数据的状态也保留入口。

会议自动起止目前保持显式操作。[信号研究](../research/meeting-lifecycle-signals-2026-10-28.md)建议先实现确认启动、长静音提醒与确认结束；扬声器静音、无语音和音源中断都不能单独证明散会。
