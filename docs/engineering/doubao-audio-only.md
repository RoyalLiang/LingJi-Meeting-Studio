# 仅豆包音频模型：转录与纪要

用户已明确选择新增此可选模式。实现使用同一方舟 Responses 地址、模型和密钥完成音频转录留证与原音纪要，不调用独立 ASR。原 ASR＋LLM、OpenAI Realtime 和豆包音频＋独立 ASR 均保留；服务失败不自动切换或生成模拟结果。

## App 配置

打开“设置与诊断 → 模型与转录服务”，将“会议理解”设为 **仅豆包音频模型 · 转录＋纪要，无需 ASR**。只需填写：

| 配置 | 值 |
| --- | --- |
| 模型协议 | Responses |
| 模型服务地址（完整接口） | `https://ark.cn-beijing.volces.com/api/v3/responses` |
| 模型 / 接入点 ID | `doubao-seed-2-1-lite-260915` |
| 方舟 / 兼容模型 API Key | 自己已开通音频模型的方舟密钥 |

保存后分别点击“测试转录”和“测试纪要”。两项仅发送合成静音。此模式隐藏独立 ASR 配置，但保留其已保存值供切回原模式使用；语音时长配额不会影响此模式，方舟自身额度与计费仍适用。

“快速记录”直接创建未命名会议并申请音源权限，无需填表。开始后打开“整理设置”，开启“自动 AI 纪要”，明确允许本场原音用于模型转录和纪要。授权前仅保存采集音频，不发送到方舟，并显示等待授权。关闭自动纪要会停止纪要更新；已经授予的本场音频处理许可仍用于转录留证。

已有因独立 ASR 配额失败的会议，切换并保存此模式后，点击语音处理提示中的“重新处理”。只补处理保留期内仍存在的原音；切换配置不会自动批量重放失败历史，也不能恢复已清理音频。既有已授权原音的会议沿用本场许可；未授权的会议先在整理设置授权。

后端等价配置为 `MINUTES_MODE=doubao-audio-only`，配合上述 `LLM_PROTOCOL`、`LLM_API_URL`、`LLM_MODEL`、`LLM_API_KEY`。App 保存配置优先于环境变量；密钥不进入 `VITE_*`，不随安装包分发。

## 转录与溯源

按音源内约 15 秒的连续持久化音频块形成短批次；原始块保留 record/session/source/epoch/sequence 和重传身份。暂停或结束后排空不足一批的尾段，不把平行音源拼成同一段。转录是模型完成的短批结果，不是供应商流式 partial。

每个转录片段记录批次时间范围、稳定 ID、修订和模型来源；此模式提供段落级时间定位，不提供逐词时间戳或声纹身份。纪要仍直接接收原音和冻结片段，引用必须通过版本校验；人工修订保护不变。模型转录可能误识别，应结合原音核对。

每批最多 128 个原始块，同时读取最多 4 个对象，批提交使用索引。批次租约和 fence 隔离重入与过期结果，停止仍等待持久确认和转录排空。失败保留原音与错误并按有界次数重试，无静默 ASR 或 mock 回退。转录请求及已报告 tokens 单独累计，且进入总模型用量；异常或旧响应已消费的用量也记录。

## 验证边界

403 项 Node 回归、ESLint、类型检查、Web 构建通过。新回归覆盖无独立 ASR 凭据的完整终稿、授权等待、短批与尾段、失败计量、过期 fence、失败历史显式重试及真实设置组件的 CLI 渲染；没有浏览器调试。

真实方舟模型使用 17.37 秒合成中文音频：18 个原始块形成两个片段，最终修复后转录约 6.88 秒，含纪要总耗时约 49.43 秒；4 条版本引用全部校验。转录两次请求共 820 tokens，整体报告 7976 tokens，仅代表此样本。未发送真实会议，未更改用户 App 配置或打开真实设备。真实多人长会议准确率、延迟、成本和实体安装后验收仍需独立验证。发布状态以对应版本 Actions 和 Release 回执为准。
