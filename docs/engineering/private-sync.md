# 加密同步测试环境

此流程供 0.4 开发分支测试使用。从桌面侧栏底部的「本地空间」使用邮箱和密码注册或登录。新账号首次登录时，客户端自动创建加密资料库。之后在手机、网页或桌面用同一账号登录，即可自动解锁同步。

旧账号在能访问历史会议的设备上打开「升级账号，登录即同步」，验证当前密码并设置新密码。升级保留原资料库和会议密文，其他设备需更新客户端并用新密码登录。云端资料库无会议和录音时，可在当前设备直接升级。若有历史资料，可在当前设备用恢复文件、已绑定的通行密钥或通过配对恢复访问后再升级。只有账号已绑定通行密钥时，浏览器才会显示该入口。

在线后从「本地空间」登录并进入「个人中心」。在「账号与同步」可设置显示名称、打开自动同步和查看已同步记录。「手机记录」提供手机快记入口和二维码。启用「自动同步本机已完成的会议」后，客户端在后台同步这台电脑已完成会议的转录、纪要和手记，包括后续修订。收到的会议版本可选择恢复到本机。

设备解锁密钥加密保存在当前应用的数据配置中。云端保存密文和账号验证记录。OPAQUE 登录在客户端生成用于解开资料库的密钥材料。清除本机应用数据后，重新登录即可解锁已升级的账号。「设备与安全」的「设备与恢复选项」提供备份入口。普通桌面会议的原音、截图、连接器密钥和声纹数据保存在设备上。
## 启动独立的 HTTPS 实例

测试域使用 `https://lingji.rookiehouse.com`。DNS 指向独立同步 API 的 HTTPS 入口。反向代理只把这个域路由到独立 Web 服务，保留原始 `Host`。云端使用单独的 PostgreSQL 和记录目录，使用运行环境的 secret 注入方式配置数据库地址和会话密钥。

```sh
export NODE_ENV=production
export RECORD_SYNC_ORIGIN=https://lingji.rookiehouse.com
export RECORD_DATA_DIR=/path/to/isolated/sync-data
export RECORD_API_PORT=3030
export WEB_PORT=3000
export RECORD_API_URL=http://127.0.0.1:3030
npm run build:web
```

用独立进程分别运行 `npm run dev:records` 和 `node apps/web/src/production-server.mjs`。两个端口均监听本机，HTTPS 代理转发至 3000。同步服务不需要启用录音或转录 worker。生产模式启动时要求 `RECORD_DATABASE_URL` 和 `RECORD_SESSION_SECRET`。

同步 API 登录挑战持久化在 `sync_challenges` 表中，支持单次消费与多实例共享。将 `RECORD_DATA_DIR/opaque-account.key` 纳入受限备份，与账号数据库一起恢复。该文件丢失会导致已升级账号无法通过密码验证。

## 在同步入口启用 HTTP/3

Android App 继续通过 WebView 访问同一 HTTPS 站点。入口通过 `Alt-Svc` 通告 HTTP/3 后，支持的 WebView 可使用 QUIC。TCP 443 继续提供 HTTPS，供 UDP 不可达或不支持 HTTP/3 的客户端使用。加密、身份验证和同步回执沿用现有协议。

独立部署可用 [Caddy 入口配置](../../apps/web/Caddyfile.private-sync)。将 `RECORD_SYNC_HOST` 设为同步域名，`RECORD_SYNC_UPSTREAM` 设为 Web 服务地址，默认 `127.0.0.1:3000`。在使用同一域名的现有入口启用 HTTP/3 时，以入口软件的配置为准。保持域名和证书有效，确认防火墙及负载均衡同时放行 TCP 和 UDP 的 443 端口。[Caddy 协议配置](https://caddyserver.com/docs/caddyfile/options#protocols)

部署后使用带 HTTP/3 支持的 curl 核对同一路径。无需登录，两个请求都应返回 401，协议版本分别为 `3` 和 `2` 或 `1.1`。

```sh
curl --http3-only -sS -o /dev/null -w '%{http_version} %{http_code}\n' https://lingji.rookiehouse.com/api/private-sync/mobile-session
curl --http2 -sS -o /dev/null -w '%{http_version} %{http_code}\n' https://lingji.rookiehouse.com/api/private-sync/mobile-session
```

在 Android 上登录并开始录音，从 Wi-Fi 切换到移动数据。核对录音连续、切换后桌面继续接收、结束后收到完整音频，并检查网关访问记录中的协议版本。APK 安装后的默认域名仍为 `lingji.rookiehouse.com`。

## 在两台设备间验证

1. 在桌面「本地空间」中注册并同步一条合成会议。在空白客户端登录同一账号，确认自动解锁并可恢复该会议。用同一账号打开手机「快速记录」，确认登录后可直接开始录音。
2. 在测试域的浏览器登录后进入「设备与安全」，展开「设备与恢复选项」，选择「信任此浏览器」。锁定当前会话，再展开「其他恢复方式」并选择「使用已绑定的通行密钥」。服务端验证 WebAuthn 的来源、RP ID、一次性挑战和用户验证。浏览器使用 PRF 派生密钥，仅上传包装后的密钥和公开凭据材料。若凭据不支持 PRF，可以用旧设备配对或恢复密钥解锁。[WebAuthn PRF](https://www.w3.org/TR/webauthn-3/#prf-extension)
3. 打开 macOS 桌面工作台，登录同一账号并同步一条合成会议。在「设备与安全」展开「设备与恢复选项」后选择「配对新设备」。在 Windows 登录同一账号，展开「从旧设备配对」，读取二维码图片或输入配对码，再回到 macOS 确认访问。密钥用 OPAQUE 导出的会话材料包裹，中继按账号保存临时密文及握手帧。[OPAQUE RFC](https://www.rfc-editor.org/rfc/rfc9807.html)
4. 在 Windows 恢复该会议，核对转录、纪要引用和手记。用一个没有该本机数据目录或通行密钥的干净设备再验证 Recovery Kit，并确认用错密钥时会拒绝。

## 开发分支范围

客户端把选中的会议修订加密后存到本机待传队列，网络中断后可重试。服务端在同一账户的行锁内分配序号，按记录个数和字节限制分页。接收设备验证密文后，在一个本机事务中保存操作并推进游标。对同一会议各自编辑形成的并行修订可分别恢复。

客户端按需重试和拉取更新。同步保留逐次快照与分支修订。自动上传由本机个人中心开关控制，已有会议的恢复需要用户选择。换钥、云端历史清理及桌面会议原音同步仍待完成。

## 手机 App 快速记录

Web 端不再提供独立的手机浏览器快速记录入口，手机快速记录统一通过 Android App（`apps/android-preview`）提供。构建 APK 时通过 `npm run build:mobile` 生成独立的手机端静态资源并直接打入 APK `assets/mobile/`，打开 App 时由 `MainActivity` 通过 `shouldInterceptRequest` 在本机离线加载界面与音频脚本（零网络等待），仅将 `/api/*` 同步请求发往同步服务。

旧 APK 联网访问 `/quick-record` 时会显示更新说明。使用同一签名的新版 APK 覆盖安装，可继续访问旧版保存的本机录音。

在手机 App 登录后点中央麦克风开始录音。波形随实际收音变化。再点一次暂停，中央按钮分开为**继续**和**结束**。录音按片写入本机，由设备可用空间和音频格式决定实际时长。保存后到**会议**回听。左滑可移除本机记录和回听副本，右滑收回操作。云端及已排队副本仍会保留。

手机和电脑登录同一账号。手机按片选择更小的无损编码并加密保存，回听仍使用 16 kHz PCM。新版可回听旧录音。使用差分压缩的新录音需要 Android 测试版 16 或更高版本回听。

手机在每次录音开始时选择服务支持的传输协议。支持 V2 的服务接收压缩音频，支持 V1 的服务接收原始 PCM 片段。服务暂时无法接收时，待传队列和本机录音都会保留。个人中心按服务返回的实际额度显示用量。

会议、纪要和手机音频每个账号共享 1 GiB。桌面落盘后确认连续游标，云端继续保留这些密文供其他设备读取。上传到达上限后，从已确认的音频前缀回收所需空间。回收后保留操作序号和密文指纹，重试会返回原始回执。如果可回收的已确认片段不足，手机保留待传内容，等桌面完成接收后继续补传。

较晚连接的电脑可能遇到已经回收的音频。它会跳过缺少开头的录音片段，继续接收后续完整录音。先前处理该录音的电脑会将原文、纪要和手记同步回原资料库。

Android 测试 APK 支持 Android 9 及以上，使用 `apps/android-preview/build.sh` 和 Android SDK 35、Build Tools 35.0.0 构建。配置 `JAVA_HOME`、`ANDROID_SDK_ROOT` 和专用测试签名文件路径 `ANDROID_PREVIEW_KEYSTORE` 后，传入 APK 的绝对输出路径。


录音通知显示正在录音或暂停以及时长，点按可返回聆记。允许应用通知后，按 Android 的锁屏通知设置显示。通过**我的 → 关于聆记**查看当前版本和查询公开 Android 测试包。点按蓝色的《音频收集告知书》可打开全文。

Android 10 及以上可通过**我的 → 会议音频自动记录**授权检测。聆记检查受支持 App 发出的进行中通话通知和系统通话模式。确认后使用麦克风，通话信号消失 10 秒后保存。通知读取权限用于核对来源和类别。要能收音，Android 还需允许聆记使用麦克风。会议 App 独占麦克风时，聆记会等待可用输入。每次开始检测都由用户在聆记内操作。[Android 麦克风共享限制](https://developer.android.com/media/platform/sharing-audio-input)

同一账号的新版桌面端接收手机录音后使用本地 SenseVoice 转录。配置文本纪要模型后，录音结束并完成转录时自动生成纪要。转录和纪要会加密回传原同步资料库，手机开启「自动同步会议与纪要」即可接收。桌面侧「自动同步本机已完成的会议」管理其他本机会议的上传。

## 设备和双重验证

新会话会出现在手机的「我的 → 设备」，新版 Android App 登记为「聆记 Android」。有效的登录会在启动、回到前台或恢复联网时检查，接近失效会自动续期。已撤销或过期的会话需要重新登录。设备离线时已经下载的资料仍由设备本身管理。

在隔离环境测试验证器时，通过凭据管理设置 `RECORD_ACCOUNT_FACTOR_KEY`，值为随机生成的 32 字节密钥，编码为 64 位十六进制。各同步实例需持有同一持久密钥，并随测试数据库保留安全备份。双重验证使用该密钥保护服务器保存的验证器种子，会议密钥照常由客户端持有。启用后，其他设备下次登录需要验证器代码或一次性备用码。

在手机的**个人中心 → 双重验证**打开设置。用 Microsoft Authenticator 添加**其他账户**并扫描二维码，也可以使用同一页面提供的设置密钥手动添加。输入验证器生成的六位码后，将备用码存放在安全位置。

使用测试账号登记验证器并保存备用码。验证只填密码时无法取得会话，然后输入备用码确认可登录，再试一次确认同一备用码已失效。在设备列表移除另一条会话，核对该会话访问同步接口时收到 401。
