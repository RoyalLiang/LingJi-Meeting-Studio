### 2026-10-12 实时连接永久中断修复

复现边界：当前开发服务正常，新建空会议直连 API 及 Vite 代理均在 3.5 秒收到 13 次心跳。历史 Vite 日志记录 API 重启时的 ECONNREFUSED。隔离代理只在首次 SSE 订阅返回一次 502，随后即恢复；旧页面持续显示中断提示，5 秒窗口内订阅请求仍只有 1 次。用户原有记录与登录会话未被替换或修改。

根因：原代码只设置提示，依赖浏览器原生 EventSource 重连。HTTP 非 200 / MIME 错误会将 EventSource 永久关闭；原代码没有创建新订阅。页头又仅使用 navigator.onLine，因而可同时出现“已连接”和“实时连接中断”。依据：[WHATWG EventSource 处理规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-eventsource-interface)。

修复：record-subscription.ts 统一管理订阅生命周期，失败后关闭旧流，以 1/2/4/8/15 秒上限退避重新读取记录及校验权限，再按最新 cursor 连接；401/403/404/410 停止重试。切换记录、退出或卸载取消请求和计时器，旧连接回调不能覆盖新状态。连接状态提示与普通业务提示分开，网络恢复重新订阅，离线切换保留当前会议界面。

同一浏览器故障注入回归：首次 502 后请求数从 3 增至 5（失败一次、恢复一次），显示 connected，原中断提示消失；后续 record.updated 事件把页面标题更新为“事件连接已恢复 · 虚构验收”。仅使用隔离空会议，不采集音频，不调用 ASR/LLM。截图 `.agent-runtime/sse-recovery-fixed.jpg`。新增回归覆盖 CLOSED 状态恢复、快照游标更新、退避上限、永久权限失败、卸载竞态、旧连接回调、事件合并及离线状态。

最终检查：70 项 Node 回归、ESLint、Web 类型检查与构建、42 份 Markdown 检查通过。主工作台热更新后确认 connected 且无中断提示。仅清理本轮创建的空开发账户验收记录和隔离进程；主服务保持运行。
