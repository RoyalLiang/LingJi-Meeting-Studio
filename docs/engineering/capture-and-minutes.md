# 音源检测与智能纪要

## 2026-10-12：采集诊断

当前本地记录的只读检查发现：一条麦克风录音的 76 个 PCM 包均已识别处理，约 74.91 秒、全部样本为零，最终没有转录。来源标签为 `System Audio`，属于自动选择规则中识别的回环设备名称。它证明选中的输入返回静音，不能证明具体哪一层系统权限或驱动导致静音。没有读取或导出用户会话文字。

自动模式继续优先系统默认，但默认输入属于明确的回环设备标签且有可识别的实体麦克风时，会选择麦克风；授权前看不到设备名时，授权后重新枚举并替换回环轨道。手动指定的可用设备始终保留。设备名分类属于启发式规则；不明确时不猜测、不轮流开启所有设备，使用逐路音量检测和试音提示排错。

浏览器的麦克风输入不包含电脑扬声器播放声。会议录音入口先在用户点击时请求共享音频，再单独请求麦克风；两路有独立来源、序列、上传与音量检测。共享成功但麦克风失败时保留共享来源并明确提示，不宣称双音源已开启。仅麦克风、仅共享音频仍可单独选择。

每路 PCM 计算音量。连续 5 秒低于检测阈值时提示检查来源，收到声音后恢复正常；同时区分浏览器音轨静音和 AudioContext 暂停。此阈值用于排错，不作为语音活动检测或丢弃音频的依据。音频仍完整保存与上传。

双源验收还发现：先启动的静音共享轨道会抢占首次说话人分配权。已改为第一条有效的、含供应商说话人编号的确认发言建立会内身份，关闭其他轨道的首次分配权。既有重连锚点与人工身份仍受保护；不同音轨之间没有可靠声纹证据时仍保留待确认，不能把编号直接当成同一个人。

设置页提供 8 秒本机麦克风试音，不上传音频。采集完成但没有文字时说明“音频已处理完成，但未识别出可用语音”，不继续展示待识别。界面将队列数量称为音频包，避免与最终发言段落混淆。

浏览器允许返回没有音轨的共享流；`systemAudio: include` 是提示，不能强制系统提供扬声器回环。应选择正在播放声音的标签页并勾选共享音频；窗口、整个系统音频支持取决于操作系统和浏览器。依据：[W3C Screen Capture](https://www.w3.org/TR/screen-capture/)、[Chrome 共享控制](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)。本应用仅处理共享音轨，不编码或上传屏幕视频。

验证：实际 CaptureController 路径的零 PCM 诊断原先失败；修复后连续静音、恢复声音、音轨静音、双源启动、缺少共享音轨和部分权限失败用例通过。另验证授权后发现 System Audio 时改选实体麦克风、保留手动选择、拒绝授权不轮询其他设备。第一阶段 74 项全量回归通过，新增设备选择 3 项与 TypeScript 通过；最终完整检查另见验收记录。物理麦克风与系统扬声器的真实声音仍需要在用户设备试音核验。
