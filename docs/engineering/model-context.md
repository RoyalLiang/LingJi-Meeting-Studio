# 配置模型的有效窗口

后端通过 `LLM_MODEL_PROFILES` 配置精确模型的能力。不要按模型名称猜测窗口、工具或缓存能力。模型配置、服务实际接受的请求和任务完成结果是不同证据。

## 先确认能力来源

保存模型连接、启动 Agent 或首次使用新模型时，服务会尝试同一配置地址下的 `/models` 和 `/model/info`，只采用精确 ID 匹配的有界字段。获取失败不会阻止保守模式；不会向其他域名跟随重定向，也不通过大请求自动探测上限。

手工配置覆盖网关元数据；元数据标为未确认。供应商超限错误中的有效上限只能进一步下调窗口。成功请求的输入量只证明已经接受过这个大小，不能据此认定最大容量。每项网关与观测事实保留来源、获取时间和确认状态；配置项的时间表示读取配置的时刻。

读取信息保存在用户数据目录的 `model-facts.json`，按服务地址、协议、模型和凭据的哈希隔离，最多保留 64 组。不保存请求正文、原文、密钥或原始错误消息。网关信息最长一天重新读取一次；切换连接使用独立记录。

LiteLLM 与 OpenRouter 的字段并不相同，网关也可能覆盖供应商限制。字段含义见 [LiteLLM API](https://docs.litellm.ai/api-reference) 与 [OpenRouter 模型接口](https://openrouter.ai/docs/api/api-reference/models/get-models)。

## 大于 256K 的窗口需要明确配置

有效窗口取标称窗口、运营限制与已观测上限的最小值。运营限制默认 262144 token；完全未知的模型继续使用 16384。更大窗口需要在精确模型配置中设置 `effectiveContextWindow`，例如：

```json
{
  "responses:example-model": {
    "contextWindow": 1000000,
    "effectiveContextWindow": 1000000,
    "maxOutputTokens": 4096
  }
}
```

将整个对象作为 `LLM_MODEL_PROFILES` 的 JSON 字符串保存到后端。示例不声明工具、结构化输出、缓存或价格，缺少这些事实时继续使用兼容路径。

一个有效窗口策略派生分页长度、分段尺寸、批量读取数、压缩预留与近期保留量。至少 64K 的模型在完整冻结来源和指引都装得下时，直接内联完整会议；否则分页或分段提炼。不会截掉原文、减少引用校验或覆盖人工修改。

已知较大窗口也会扩展文字纪要的输入与综合窗口，最大 384000 字节。未知模型保留现有 24000/96000 字节兼容边界；显式的 `RECORD_MINUTES_INPUT_BYTES` 和 `RECORD_MINUTES_SYNTHESIS_INPUT_BYTES` 继续生效。音频仍按原有时长处理，不因文字窗口变大而扩大原音外发范围。

## 预算按材料估算，运行中逐请求预留

准入预估根据材料大小和读取策略估算轮数，输入量不会再按“最大轮数 × 整个标称窗口”计算。预估轮数与任务硬轮数上限分别保存。

设置单任务预算时，需要完整的精确价格配置。每次请求前，按请求大小的保守字节上界、指引余量与输出上限累计预留，超出预算即停止；压缩、重试和子任务共享这一约束。预留不会假装成供应商账单，未知价格或不完整 usage 不能显示为零费用。Git 同步弹窗仅显示交互式进展，保留后台诊断计量。

压缩和内联判断使用中文、英文及 JSON 结构字符的启发式估算。只有某类字符占比至少 80% 的实报 usage 样本才校准该类比例，并保留安全余量；混合请求不足以同时反推三种比例，不据此提升模型容量。实际 tokenizer、缓存和供应商计费仍需分别核对。

## 超限先压缩，不降低工具能力

适配层把确认的超限错误转换为安全的 `context_length_exceeded`，保留 Pi 的一次压缩再重试路径。再次超限会停止，不循环重试。只有明确报告不支持工具参数的错误才触发兼容模式；普通 400/422 不再用于判断工具能力。

主任务的最终引用不合法时，在同一持久化会话中修正最多一次。修正阶段禁止归档或重新对账写入，仍要通过冻结来源与引用校验。连续运行中断有明确的失败状态和重启上限。

运行中补充问题仍通过现有问答与暂停恢复处理。独立分叉、更多工具搜索入口和分角色模型配置不属于当前流程；MCP 仍只暴露用户已选的只读工具。真实长会议与供应商网关延迟需要独立验证，参见[当前能力与边界](current-state.md)。
