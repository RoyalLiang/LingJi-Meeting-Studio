# 运行会议与 Git 任务

会议助手、纪要整理和 Git 同步共用持久任务内核。任务保存材料范围、来源修订、阅读进度、已答问题和用量；重启后按原范围恢复，不把上下文检查点当作任务完成结果。

## 在后端维护模型事实

设置页只保留服务连接与模型选择。模型上下文、输出上限、原生工具、严格格式、并行只读工具和缓存能力通过后端 `LLM_MODEL_PROFILES` 登记；键为 `协议:模型`，已有配置继续生效。不要从模型名称推断容量。未知模型使用保守的兼容模式。

`MEETING_TASK_BUDGET_USD` 控制后台预算，0 表示不设金额上限。单价缺失时费用保持未知，前端不展示费用。服务商未报告的 token 不记为 0；界面累计已报告的轮次、压缩和 token，失败请求已产生的用量也保留。网关组织额度可能同时被其他客户端消耗，本地预算无法保证上游不会拒绝请求。

## 阅读、推断与外部写入分别处理

Agent 分页读取会议材料；大上下文模型可在一次模型轮次请求多页，已读进度保存在检查点。近音专名可以结合上下文和词表提出规范词，明确推断依据；歧义词保留待核实，原始文本、引用版本及人工编辑不被自动替换。

Git 只读目录和文件查询可以先执行。归档或对账写入前，必须读完所选会议页，并再次校验 owner、来源、规则、目标和写入范围。外部请求结果未知时，核对原先冻结的内容与远端回执，不直接生成第二份归档。

## 暂停和继续原任务

暂停先保存写入围栏，并取消活跃模型请求；已提出的问题保留回复位置。继续任务时自动复核已保存配置，不要求先执行范围检查。模型配置变化且仍待回复时，保留问题；提交回复后，把问题与答案带入采用新配置的 Agent，保持同一归档身份。

已经进入外部写入的任务保留原写入与对账围栏，不因为更换模型或规则自动重建归档。暂停不能撤销远端已经接受的请求，也不能撤回供应商已经产生的用量。

## 查看进展与诊断

任务过程与用量直接显示，包括等待录音结束、等待空位、模型请求、上下文压缩和工具阶段。进度来自实际事件，不能用动画或估计百分比代表供应商完成度。下载诊断仅用于定位任务状态；生产和真实会议验收需单独记录，合成测试不能替代。
