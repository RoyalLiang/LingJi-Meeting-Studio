# 保存、检索与长会议的性能边界

## 高频音频写入使用独立集合

SQLite 和 Postgres 将音频块、转录片段、事件、任务及纪要历史放在独立集合中，较大的纪要、洞察和学习内容放在文档表中。主体保存会话、来源和版本元数据。写入仍在同一事务内维护游标和投影，人工正文不会因后台局部更新而被覆盖。

音频接收先持久化原始文件，再更新对应块、连续确认水位和缺口范围。重复包校验摘要，不会重复插入。接收和实时草稿更新不需要载入整场转录。复杂度受音源数量、缺口和返回结果大小影响，不能将所有操作都称为严格 O(1)；最终转录、完整记录编辑和重新整理仍有聚合处理。

SQLite 继续使用 WAL 和 `synchronous=FULL`。迁移前创建一致性备份；从旧格式升级分别使用 `records.pre-collections-v1.sqlite` 或 `records.pre-collections-v2.sqlite`，备份失败会阻止迁移。不要只复制运行中数据库的主文件。回退旧版前，应停止后台并恢复匹配版本的完整备份。

## 流式更新和事件位置

纪要流式预览只更新当前任务的预览与运行状态；单句翻译只读取并更新候选片段，沿用代次、转录修订和租约校验。它们在同一事务内追加事件、维护续传游标和列表更新时间，不重新编码整场音频、转录或搜索投影。公开任务列表仍按既有协议返回全部任务；成本仍受任务历史与返回结果大小影响。

SQLite 的小容量缓存采用版本匹配的写穿更新。任务预览先合并轻量字段，完整读取时才解码冻结输入；跨进程版本变化、未知修改或不完整补丁会失效缓存。事务回滚后数据库版本不同会强制重读。事件环使用单调绝对位置，仅删除过期头部并追加新事件，普通字段修改不会将整个事件环重排。

## 检索和读取按需进行

目录概览、配额、删除状态和任务候选读取可查询元数据。各记录工作通道先查询到期元数据，仅在执行需要时读取完整内容；工作区任务使用独立元数据。候选查询与唤醒查询共用到期表达式索引，保留按 ID 游标轮转的公平性。大量任务同时到期时仍需处理到期集合，不能据此宣称所有调度为 O(1)。SQLite 使用 FTS5 候选和 BM25 排序，Postgres 使用 GIN 候选，并保留字面匹配校验。结果仅返回有界摘要和对应原文高亮，不扫描记录标识或内部历史作为用户正文。

转录与译文使用动态行高虚拟列表，通常保留 30–50 条热行；正在编辑的行可额外固定。搜索、定位来源、尾部跟随和人工编辑继续使用稳定片段标识。

## 录制不依赖主窗口搬运 PCM

桌面本机后台使用 `native-file-v1`：Rust 将有校验和的 PCM 帧写入私有落盘目录，Node 接收后才返回持久化确认。主窗口只读取进度。后台会恢复已落盘帧和停止栅栏，旧实例不会自行重新打开设备。真实设备失败不会替换成合成音频。

浏览器录音保留 IndexedDB 待传队列和二进制 PCM 上传。两条路径都核对 record/session/source/epoch/sequence、摘要、重传幂等和停止排空，不能在最终确认前丢弃尾包。

Worker 使用变更通知唤醒；Postgres 通过独立 LISTEN/NOTIFY 连接接收提交后的通知，断线重连和定期核验补齐漏通知。SQLite 使用文件变更及数据版本核验。低频恢复检查仍然存在，不宣称完全没有轮询。

## 长音频按片段解码

支持的音频容器由 Mediabunny 和 WebCodecs 分片读取、解码、重采样，避免整文件展开为浮点 PCM。上传保持顺序并等待有界待传队列排空，取消会停止后续读取。

内核缺少 AudioDecoder 时仅允许有界 AudioContext 回退：文件不超过 64 MiB、时长不超过 15 分钟、预计解码内存不超过 96 MiB。超过边界会说明原因，不能承诺所有格式和所有浏览器均可导入任意长文件。不同编码、浏览器原生采集和真实长会话仍需分别验证。

## 分开理解测试证据

自动化检查覆盖迁移备份、事务回滚、重启、跨连接通知、重传、乱序、停止栅栏、检索、虚拟列表和来源修订。合成大记录基准测的是对应存储路径；公开语音模型样例测的是模型与处理链。它们不等于原真实会议、物理双路录音、PG/S3 部署或跨平台设备验收。
