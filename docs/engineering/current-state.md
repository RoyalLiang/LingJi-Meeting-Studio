# 当前能力与验证边界

当前源码目标版本为 **0.3.3**。发布状态以 [GitHub Release](https://github.com/RoyalLiang/lingji/releases) 和对应 Actions 结果为准；本地检查通过不等于安装包已发布或目标设备已验收。

## 已实现的工作流程

- 浏览器工作台与桌面客户端共用 Record API。录音使用 record/session/source/epoch/sequence 标识、持久化确认、重传去重和停止排空。
- 转录、AI 纪要、译文和引用分别保存修订；人工编辑不会被自动重生成覆盖。
- pi 会议任务支持材料分页、来源引用、上下文压缩、暂停恢复、问题回复和运行诊断。Git 同步固定目标仓库与写入范围，对未知写入结果先对账再恢复。
- Agent 与纪要生成在原有处理轮次中识别近音专名候选。明确规范写法与待核实推断分别说明，原始转录和引用版本不变。
- 模型能力和预算配置由后端维护，精确网关元数据、实报用量与超限上限分别记录来源。有效窗口驱动 Agent 读取、压缩和已知模型的纪要分窗，见[模型窗口与预算](model-context.md)。
- 版本更新由可点击的版本标记进入；已检查为最新时显示 latest，有更新时显示箭头。Git 同步弹窗保留问答与进展，计量继续保存在诊断数据中。

## 分开看待不同验证层

合成测试覆盖协议、SQLite 持久化、权限与任务恢复、渲染、安装包契约。原生 CI 分别验证 macOS、Windows 和 Ubuntu；Linux/Windows 安装包在 WGS 当前代码目录构建，macOS 在 GitHub Actions 构建。

浏览器原生采集、Postgres/S3、真实 ASR/LLM 的内容质量、供应商网关延迟、实体设备音源与长会话需要各自证据。词语候选和引用不能保证模型理解正确；新规则不会自动重处理已有纪要。
