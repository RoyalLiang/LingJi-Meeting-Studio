# Node 26.12.1 本地安全升级

2026-10-31。范围：源码、开发/CI配置和本机生成的桌面后端资源。**仅本地验证，尚未推送、发布或替换已安装客户端。**

[官方发布说明](https://nodejs.org/en/blog/release/v26.12.1)确认这是2026-10-21的安全修复版，涉及TLS、DNS和Brotli等高危问题。按用户要求固定到26.12.1；本轮不宣称这是所有后续版本中的最新安全版本。

## 改动

- `.nvmrc` 固定26.12.1，根包与lockfile声明Node `>=26.12.1 <27`；开发者需用自己的版本管理器选择该运行时，系统Node未被修改。
- 两套客户端工作流的7处Node选择均固定26.12.1。随包准备脚本同步四平台官方SHA-256，保留下载校验、架构、隔离导入和FTS5检查；Apple Silicon实测SQLite为3.54.0，包内启动检查同步更新。
- Node26移除了测试夹具的TypeScript `transform` 模式。涉及参数属性的四组夹具改用共享esbuild转换，保留原来只需strip的调用。esbuild0.25.12原已在lockfile和本机安装，本轮仅声明为直接开发依赖；没有新增生产依赖或改动会议处理算法。
- 会议Pi报告继续比较durable、SDK和core，强调会议资料范围、引用、人工编辑保护、Skill/插件版本和任务生命周期；没有集成Pi或编码工具。

## 验证

完整数据见[验证与性能JSON](../evidence/node26-runtime-2026-10-31.json)。Node24.21基线386项回归通过；Node26本地工作树386项回归、ESLint、typecheck、Web构建、随包后端准备/隔离导入及21项Rust回归通过。工作树包含用户原有播放实验，原改动不纳入本轮提交；仅含本轮改动的暂存快照另通过385项Node回归、lint、helper单独lint、typecheck及Web构建。独立评审未发现本轮阻塞问题；两份快照相差用户原有新增的一个播放测试。

隔离后端检查确认Node26.12.1/SQLite3.54.0、独立本地账户、开发账户关闭、父进程退出与重启持久化，未请求开发后台。此检查没有启动原生App/WebView。合成升级路径也通过：Node24创建会议、人工笔记/纪要及音频，Node26读取和保存，再由旧运行时回读；片段/纪要版本、人工内容与音频字节保持。

启动、存储、SSE各按24/26交替运行3次，下表取每次指标的中位数：

| 指标 | Node24.21.0 | Node26.12.1 |
| --- | ---: | ---: |
| 100场合成历史的后台就绪 | 29 ms | 26 ms |
| 两小时合成会议的压缩写入P50 | 35.26 ms | 32.65 ms |
| SQLite提交到SSE的P50 | 100.70 ms | 101.05 ms |

未见明显退化；约0.35ms的SSE差异没有统计显著性依据。样本较小，不能外推真实ASR/LLM、长会议、用户设备或完整App冷启动速度。内置Node二进制从122,129,232增至147,346,352字节；这不是压缩安装包增量。

## 边界与回退

仅实跑macOS arm64；其他三平台目前只核对官方清单并更新配置，待各自环境/CI验证。没有重新安装依赖、触发远端CI或生成发布安装包。未打开真实音频设备或调用真实供应商；Pi调度、插件兼容和故障恢复仍是后续隔离验证提案。

源码回退应整体恢复运行时版本、四平台校验和及包内SQLite断言，不只替换一个版本字符串。旧运行时仅用于本轮隔离基准及数据兼容性检查；生产应继续使用含安全修复的版本。真实数据操作前仍应完成一致备份；本轮没有访问或迁移用户数据。
