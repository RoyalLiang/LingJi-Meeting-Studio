# 迟到转录、上下文与纪要更正

这轮改动准备交给另一会话统一发版。本轮不修改产品版本，不创建标签，不触发构建发布工作流。

## 发言时间与整理频率分开处理

自动整理仍支持 15、30、60、120 秒。整理频率决定何时处理新增内容；两分钟分窗和上下文范围用于控制单次输入大小，不能代表一句话或一个议题已经结束。

纪要快照按发言时间排序，保留原始到达顺序和冻结修订。迟到片段会取得发生时间前后两分钟的已有转录；未覆盖的新片段仍全部纳入。没有可靠时间时，使用相邻片段。分窗还会在预算允许时带入前后相邻的文字上下文，并标记 `contextOnly`。

历史主题、决定、行动和正文事实组成最多 12KB 的记忆，最多带 40 个事实。优先选择与当前主题或证据相关的内容。历史事实带稳定标识，原文回填仍经过分窗预算；上下文本身不能冒充本轮新证据。意图分析保留最近到达片段，再按发言时间排序，携带时间、来源和会内说话人信息，避免先按时间截尾而丢掉迟到片段。

用户已明确授权：意图分析可在本场既有 AI 分析授权下，将这份有界同场历史记忆发送到后端当前配置的 `LLM_API_URL`。目标地址不由本轮修改。未开启本场分析授权时，继续使用本地规则。

## 更正旧理解，并保留来源

未完成表达、条件未满足、指代不清、提议和转述不应直接进入有效决定。文字、豆包音频和 Realtime 使用同一套规则，并按会议、访谈和学习笔记选择整理目标。

新增证据可以通过 `corrections` 指向历史事实：

```json
{
  "targetId": "fact-原事实标识",
  "status": "withdrawn",
  "text": "取消周五上线，等待安全评审。",
  "evidence": [{ "segmentId": "新片段标识", "revision": 1 }]
}
```

状态为 `pending`、`corrected` 或 `withdrawn`。目标必须来自本轮可信历史记忆；引用必须包含本轮新增转录，不能只引用旧上下文。非法目标、重复目标、未知引用和缺少新证据都会失败。窗口、缓存、汇总和最终提交共用校验。

事实身份由服务端依据文本和冻结引用生成，不信任模型的局部条目 ID。应用更正时，目标旧事实从活动正文、决定和行动中移出，依赖旧证据的表格、图表与发言人摘要失效，相关主题摘要等待重写。其他共享引用的事实不能被直接判为已撤回：原文、负责人、日期和引用保留，转为“待复核”，避免正文改写继续作为有效承诺。关联项保留独立身份，不随其他事实后续更正而删除。正文显示带来源的更正说明，最多保留 100 条更正审计及被更正事实。更正后仍有效的决定和行动须由模型完整重写，包括负责人和日期；显式 `null` 会清空旧值。现有分享和导出读取相同活动集合。

并发窗口的部分结果按窗口顺序重放；同一事实及其更正说明共享根身份和当前状态时间。更正时间只取本轮新增证据，较晚的旧上下文不能抬高更正时间。较早证据不能覆盖后来的状态；包含过期更正的整批替代内容转为待复核，不能通过配套决定或行动重新激活旧事项。原有 generation、fence、人工编辑保护和冻结引用检查继续生效。

## 汇总时提供有界原文

分层汇总在摘要和引用元数据之外，增加预算内的原始转录。优先提供决定、行动、更正及较晚证据，原文字节最多 24KB，且不超过本次汇总总预算。未能提供的原文会标记 `textOmitted` 并计入 `omittedEvidence`；提示词要求保留未解决分歧，不能把摘要视为完整原话。

音频路径不追加跨窗口原音；保留既有样本、时长、授权和来源限制。文字上下文的改动不等同于已完成真实音频质量验证。

## 可选的结构化输出

默认继续使用 JSON mode。仅在确认供应商支持严格 JSON Schema 后，在后端环境设置：

```dotenv
LLM_STRUCTURED_OUTPUTS=true
```

该选项对文字及豆包 Responses 纪要生效。Realtime 继续使用其既有文本响应接口。供应商拒绝该格式时明确报错，不静默切换模型或降级。结构约束不能证明引用语义正确，领域引用和更正校验仍会执行。

## 运行评测

```bash
node --test tests/records-minutes-context.test.mjs tests/records-minutes-pipeline.test.mjs
npm run evaluate:minutes
```

默认评测只运行本地规则，覆盖 12 个合成场景，包括条件承诺、事实否定、反问、转述、未说完、跨窗补充和乱序撤回。测试另覆盖前后文、跨项目隔离、显式清空、非法更正、派生视图失效、并发完成顺序及汇总预算。

要使用配置的真实模型评测这些合成文本，显式运行：

```bash
npm run evaluate:minutes -- --provider --output /tmp/minutes-provider-eval.json
```

该命令会读取本地 `.env`（存在时），调用意图和纪要模型，并产生供应商费用。报告包含意图匹配率、按预期证据计算的决定精确率和召回率、耗时及生成结果。它不是完整语义评分；同义表达、条件是否完整和引用是否支持结论仍需人工审查。

本轮的自动化结果只能证明本地逻辑与合成夹具行为。真实会议语义质量、长录制、实体采音、真实供应商兼容性和部署结果须单独验收。

## 2026-10-26 持续会议冒烟与停更修复

本轮只更新独立分支，不递增版本、不创建标签、不触发发布。

本地合成复现：SenseVoice 批次每 30 秒提交一次转录，每次模型输出 3 节有效纪要；第 7 次更新（模拟会议第 3 分 30 秒）累计 21 节，被单次 20 节限制拒绝，转录仍在推进。会中临时失败在转录版本未变化时也不会重试。

修复将单次模型输出与内部累计结果分别校验：单次输出仍保留原上限；累计容量按服务端冻结的唯一转录版本增长，分窗预览另计服务端基线及已完成窗口数。人工保存采用服务端既有证据快照，客户端不能扩大容量或伪造引用。临时错误沿用 15 秒、30 秒退避，合计最多 3 次；人工编辑、关闭自动纪要、永久错误仍阻止重试，新转录重新开始一次正常更新。

长会议提示词的标题、主题、章节名、摘要合计最多占 6KB，给旧决定、更正目标和近期要点留出空间，总预算仍为 12KB。模型重用被裁剪主题的 ID 时，服务端为新主题重新编号并只重映射新事实，旧项目的行动与负责人保持原归属。

冒烟覆盖真实仓储持久化、PCM 确认、本地 ASR 批处理适配器、自动调度、分窗与累计纪要、HTTP 人工编辑。12 分钟合成时间线连续 24 次更新并保留首尾要点；识别器与模型输出使用注入夹具，不发起真实 ASR/LLM 云端请求。此证据不能替代原生 SenseVoice 模型推理、真实长会议录音、浏览器采集和已安装客户端验收。
