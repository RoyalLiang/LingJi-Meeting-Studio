# 客户端更新先验签，再确认会议安全

更新日期：2026-10-13。本文描述本地已实现行为；GitHub 发布、正式签名和三系统安装验证仍待完成。发布步骤见[GitHub 客户端发版](../releases/github-client.md)，技术依据见[调研](../research/git-release-and-client-updates-2026-10-13.md)。

## 在桌面端设置中管理更新

Tauri 客户端的设置页显示当前版本、更新状态、下载进度和错误。Web 与移动浏览器不显示这一节。

- 用下拉框选择“手动检查”“自动检查”“自动检查并后台下载”；默认自动检查。
- 自动检查在启动约 10 秒后触发，此后每 6 小时检查；失败后至少间隔 15 分钟。
- 后台下载默认关闭。开启后可在会议期间下载，下载会使用网络和磁盘空间。
- 安装必须手动点击“重启更新”，只在已登录、会议结束且补传完成时允许；旧版自动安装偏好会关闭。
- 可以分别手动检查、下载和重启更新。下载完成不等于允许立即退出。

macOS 顶部菜单栏右键菜单也提供检查更新、自动后台下载开关与重启更新。菜单显示版本/进度和禁用原因，状态过期、缺少可信源、录音或待传队列时禁用对应动作；点击重启仍重新执行全部安装门禁。

检查使用定时器和联网事件，每 30 秒判断是否到期，不每秒轮询网络。偏好保存在当前服务的本地 WebView 存储中。

更新源和信任公钥必须在构建时配置：`TTS_UPDATER_ENDPOINT`、`TTS_UPDATER_PUBLIC_KEY`。缺少任一项时显示“尚未配置可信更新源”，不启用更新。正式构建只接受 HTTPS，下载重定向也受 HTTPS 限制；测试构建的本机 HTTP 例外不会编入正式包。客户端不携带 GitHub 下载令牌。

## 安装同时通过本地和服务端检查

点击安装时先冻结页面操作，再重新读取整个 IndexedDB 音频队列。检查范围包含当前页面未展示、其他记录和其他账户留下的待传片段；不以列表是否为空代替队列检查。存在待传字节、片段、保存中或上传中操作时拒绝安装。

Rust 层独立检查正在采集、权限请求尚未结束、安装互斥锁，以及前端状态是否在 4 秒内更新。录音、暂停待继续、繁忙和未登录状态均被阻止。安装开始后禁止新原生采集、页面导航和关闭请求；安装失败后释放保护，页面可以继续操作。

随后用本地代理中私有的登录会话请求 `GET /api/client/update-barrier`：

```json
{"protocol":1,"records":[{"capture":"sealed","sources":[{"stopped":true,"lastSequence":3,"watermark":3}]}]}
```

接口只返回当前账户未删除、未过期的 Record 的采集状态与来源停止/ACK 元数据，不返回标题、记录 ID、音频、转录或密钥。每个来源必须明确停止，服务端持久化水位必须覆盖 `lastSequence`。没有来源的空记录可以通过；缺字段、未知状态、未停止或 ACK 不足均拒绝安装。ASR 与 AI 任务可以在服务端继续，安装不等待它们完成。

当前策略较保守：同一账户的其他未结束或暂停会议也会阻止安装，即使当前页面已结束。这避免筛选、切换记录或重登后漏掉待继续的会议。后续若要缩小范围，需建立可信的客户端会话归属，而不是放松检查。

后端不支持协议 v1、登录过期、接口超时或返回异常时，下载可以保留，安装失败并显示原因。先升级后端，再推广启用更新的客户端。运行中的 API、worker 和已有录音不会由发版脚本自动重启。

## 更新文件通过两层完整性检查

使用官方 `tauri-plugin-updater 2.13.3` 验证制品签名及签名中的版本；声明版本与签名版本不一致时拒绝下载结果。下载总量限制为 256 MiB，总超时为 180 秒。缓存前检查剩余磁盘空间，Unix 缓存文件权限为 `0600`。

安装前再次检查缓存长度、SHA-256 和磁盘空间，避免下载后文件被替换或损坏。只有当前进程验证过的缓存可安装；重启后需要重新检查和下载。下载与安装操作串行执行。

macOS 使用 `.app.tar.gz`，Windows 使用 NSIS 安装包，Linux 首轮使用 AppImage；Linux 的非 AppImage 安装显示手动升级提示。官方安装器可能退出当前进程，因此所有安全检查都在调用安装器之前完成。

## 先建立可更新的可信版本

已有本地 Alpha 没有可信更新公钥和更新源，需要在录音结束、补传完成后手动安装首个正式配置的版本。新增功能不能让旧安装包自动获得更新能力。

首轮只提供 stable 自动更新；预发布版本可以作为 GitHub prerelease 供手动安装，不成为 stable 的 `latest`。尚未实现渠道切换、灰度队列、差分包、启动健康确认或自动回滚。版本/协议需保持至少相邻版本兼容，数据迁移另行设计和验证。

## 重复验证

```sh
npm run test:client:updates
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo build --manifest-path apps/desktop/src-tauri/Cargo.toml --features smoke-test
node scripts/test-client-updater.mjs docs/evidence/client-brain-research/client-updater-smoke-2026-10-13.json
```

原生更新场景脚本当前在 macOS 执行，创建临时签名密钥、临时 API、独立 WebView 数据目录和替身 `.app`；结束后清理。它验证官方更新器实际替换替身应用，不更新已安装客户端，不打开真实音频设备，不访问真实模型。验证分层与结果见[更新验收证据](../evidence/client-brain-research/client-updater-validation-2026-10-13.md)。
