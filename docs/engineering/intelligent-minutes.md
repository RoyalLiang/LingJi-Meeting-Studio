# 智能纪要主阅读区与实时翻译

核查日期：2026-10-12。本页描述当前实现；真实模型的总结质量、翻译准确率和长会话表现仍待验证。

## 会中直接阅读纪要

主区默认显示智能会议纪要：录音控制下是紧凑工具栏、连续主题树与总结表格，人工笔记保留在下方。搜索框位于右侧容器顶部中央，搜索当前工作目录内的会议与内容。AI 视图按主题阅读，也可切换表格与图表、发言人总结、关键决策和正文。既有未启用 AI 的会议仍需主动点击开启自动纪要；保存模型配置不会静默上传这些会议。

“当前正在聊”固定在主容器底部，主内容可以独立滚动。等待模型时显示轻量三点动效，收到输出后显示 agent 草稿或已归纳要点；原始转录和 ASR 草稿不会充当 agent 总结。已有要点等待下一轮更新时保留来源，完整结果核验前的模型草稿不能作为正式结论。底部生成内容可独立跟随，手动向上阅读后点击“最新要点”恢复；系统设置减少动态效果时停止等待动画。

总结表格按讨论内容生成，每行带来源；已有行动候选可自动汇总成事项、负责人和时间表。缺少负责人或时间时显示待确认。表格可复制，手机在表格内部横向滚动。图表只统计本版实际主题、决策、行动候选及引用覆盖；数量和覆盖不等于模型准确率，也不表示会议所有内容都已归纳。

会中更新自动跟随。向上阅读、编辑、切换历史或查看引用时暂停；暂停状态跨录音和纪要任务阶段保持，点击“回到最新纪要”才恢复。该按钮在阅读区下方占用独立一行，不盖住正文或底部讨论区；无纪要时不显示。确认原文及纪要的版本引用继续保留；来源弹窗读取对应冻结修订，人工纪要不会被后台重生成覆盖。新录音默认保留原音，既有记录保持原策略，见[运行手册](runbook.md#留存与删除)。

## 说话后由转录驱动 agent 总结

点击**快速记录**即可开始说话，不需要先手工输入或导入文字。当前后台链路为浏览器采集音频 → ASR 实时识别 → 保存带片段 ID 和修订的确认文字 → agent 根据文字生成纪要。纪要请求只包含转录快照和人工笔记；尚未实现把原始音频直接提交给纪要 agent 的多模态理解链路。

录音权限和转录服务就绪后可以采集；模型配置就绪且开启自动 AI 纪要后，确认文字会按整理间隔触发总结。识别草稿尚未确认时，底部保持等待状态，不会把它当成已经生成的总结。实现依据：[浏览器采集](../../apps/web/src/audio/capture.ts)、[说话人识别流](../../services/records/src/speaker-streams.mjs)和[纪要文字请求](../../services/records/src/providers.mjs)。

## 需要译文时打开实时翻译

原纪要按钮的位置现在是“实时翻译”。点击后默认翻译为英文，也可选择中文、日文、西班牙文、法文或德文。开启会处理本场已有和后续确认原文；关闭面板继续处理，点击“暂停翻译”才停止。译文可查看对应原文，失败状态明确显示。

翻译固定使用专用豆包 Responses 模型 `doubao-seed-translation-250915`，逐段请求确认原文。它不是供应商流式 partial。`DOUBAO_TRANSLATION_API_URL/API_KEY/MODEL` 与纪要配置分开；URL 按填写值使用。未设专用 URL 时复用纪要 URL，密钥只有在实际 URL 相同时才可回退使用纪要密钥；不同地址需要专用密钥。切换语言或暂停后，目标修订与任务 fence 阻止旧请求回写。详细配置见[实时翻译运行说明](runbook.md#实时翻译)，请求结构见[实际 API](api.md#智能纪要结构与实时翻译)。

## Alpha 11 阅读与分享修订

录制完成后隐藏底部会中讨论区，主区直接展示智能纪要。旧会中或旧转录失败不覆盖新终稿。来源弹窗显示该版引用前后文、时间和说话人，精确匹配片段修订，不回退当前人工文本。

分享入口在有记录时可打开；无内容时在弹窗内提示。独立客户端可导出供浏览器阅读的HTML文件，默认仅纪要与必要引用；需要全部转录时明确选择。部署到可访问站点时可生成24小时可撤销链接。不会自动上传或向他人发送内容；原音不包含在分享中。

## 纪要底部用量

底部显示本场已接收音轨累计时长与已确认纪要token；供应商实际返回时展示输入/输出细分。未知用量不写0，实报0才显示0；旧的跨AI累计字段不作为新主数。供应商用量帧到达即经SSE更新，若供应商只在结束时返回，就只能在回传时确认。缓存复用不重复统计，每次真正重试分别统计，已产生用量不会因内容失败消失。token计数不是费用账单，ASR当前无token计量。
