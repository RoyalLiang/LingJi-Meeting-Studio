# 后台会议联动：浏览器与飞书音频调用

更新日期：2026-10-31。已随 v0.2.4 发布；[发布核验与验收边界](../evidence/preview-v0.2.4-2026-10-31.md)。首版只支持 macOS 14.6+ 桌面上的 Chrome、Edge 和飞书。v0.2.5 候选增加 Windows 10/11 的共享音频会话；Linux、Safari 及共享 WebKit 进程暂不启用。

## 开启与停止

在**设置与录音环境 → 后台会议联动**中，勾选**允许音频调用触发自动录音**，选择浏览器或飞书，然后保存配置。默认关闭；转录、模型服务和系统采集权限需要先配置。启用意味着允许所选目标触发麦克风与系统音频录制，并沿用当前转录和纪要设置；直接音频模型的独立授权仍保持原规则。

原生进程每两秒读取 macOS CoreAudio 或 Windows WASAPI 共享会话的输入/输出运行状态，不靠音量、RMS 或是否有人说话判断。所选目标持续调用输入或输出至少十秒后，经可取消倒计时开始；所有所选目标停止调用至少三十秒后，经可取消倒计时结束自动创建的记录。采样、权限和队列会增加实际等待，不承诺精确十秒或三十秒。

- 普通静音、系统音量零或安静听会，只要音频调用仍运行，就不作为结束条件。
- 音频调用恢复会取消结束候选。读取失败、睡眠或采样中断、时钟跳变及过期事件，会重置候选，不把未知状态当成停止。
- 手动开始、暂停或结束的会议不由联动接管。手动停止后，当前持续音频调用不会立即创建新会议。
- 取消结束候选或关闭联动，会把当前录音交回人工控制，不自动终止它。切换监听目标仍保留自动会议归属，并重新等待稳定状态。
- 结束复用现有停止排空流程：保存尾段、封存采集，上传、转录与未完成纪要继续处理。

macOS 关闭主窗口会继续驻留；可以从 Dock 或菜单返回。**退出聆记、崩溃或系统睡眠不能承诺继续监听和录音**。本轮没有安装系统守护进程、开机自动启动任务或日历集成。

## 首版限制

这是按音频调用联动，不能识别真实的入会、离会或会议实例。浏览器播放视频、音乐或长音频也可能触发；同一浏览器的不同标签页和多个会议不能可靠拆分。飞书的其他持续音频功能也可能触发。检测目标应用不等于只采集该应用：当前系统音频来源可能包含其他应用声音。

Chrome/Edge 与飞书的主进程、已核对的音频 helper 使用精确 bundle ID 白名单，排除聆记自身、Ego 和共享 WebKit。未识别的新 helper 可能漏触发，后续需按目标应用版本验证。Safari 的共享 WebKit 归属不可靠，因此首版不纳入。

## 本轮验证

十一项状态机用例覆盖开始/结束窗口、短通知、调用恢复、人工覆盖、取消、目标切换、采样错误和冻结后的过期事件。原生实际采样源码的独立 ABI 故障注入覆盖八类读取错误，验证 unknown 不推进结束，以及 CFString 释放。原生编译/回归和完整 Node 回归另见[本轮证据](../evidence/rolling-summary-2026-10-30.md)。

本机 CoreAudio 元数据读取返回有效的无目标活动结果；未打开真实采集设备或触发个人会议。真实 Chrome/Edge/飞书活跃调用的 helper 归属、长会话误触发率、设备切换、锁屏连续性和耗电仍待试点验收。长期方案和更多场景见[后台起止设计](../design/background-meeting-lifecycle-2026-10-30.md)。

Windows 保留输入/输出端点的 manager、通知和会话引用，按进程映像文件名核对 Chrome/Edge、飞书，读取失败或归属不明不推进结束。监听不打开音频流。独占音频不在当前可观察范围；共享会话切换到独占流可能不可观察，应使用手动控制，不能把这条路径称作完整会议状态识别。详见[微软主源研究](../research/windows-meeting-audio-watch-2026-10-31.md)。
