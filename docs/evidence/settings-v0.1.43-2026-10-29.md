# v0.1.43 录音保存与设置、纪要界面修复

日期：2026-10-29。基线：ed0e818（v0.1.42 发布回执）。本地验证完成，发布核验待补记。

## 已确认的问题与修复

- 队列选择待上传片段时，周期唤醒会丢弃已选片段并重新选择。在慢 IndexedDB 与连续唤醒下，上传被饿死。删除对纯唤醒的重选，保留持久化 ACK 代次变化检查。
- 空队列后台扫描也标记为 queueBusy。仅在本地写入或真实存在待传片段时标记忙碌，保留队列字节数、原生采集、停止屏障和服务端确认等独立保护。
- FeedbackNotice 默认使用 inline，导致纪要、转录服务错误占据正文高度。统一默认浮层；保留重试、关闭和同一故障确认语义。
- 设置更新说明移入现有 Modal，Escape 仅关闭最上层弹窗，底层配置草稿保留；更新区域从约 380/520 px 收紧为约 115/520 px。
- 纪要保持既有树形卡片字号与间距，恢复小结和标题背景；移除顶部处理详情。逐字记录入口移动到纪要标题栏，隐藏时不重复计算全部片段，首次展开后的编辑草稿保持挂载。

## 验证

1. 新队列测试先复现两项失败，修复后通过：连续六次唤醒仍在首轮选择后上传；空队列扫描不误报保存中。
2. 真实本机 HTTP/SQLite 集成：先封存最后序号，再排空六段持久化 PCM；确认最后序号和 watermark 均为 5、停止确认成功、原音 WAV 字节完整可读取，此时 ASR 六段仍待处理。证明原音解锁与 ASR/纪要无关。
3. 队列、原生客户端、播放状态定向回归 52/52；独立音频链路复审 103/103，无已确认 P1/P2。最终全量 npm test 653/653，通过 lint、typecheck、build:web、check:docs 与 diff --check；发布构建与附件核验待回执补记。
4. 实际浏览器使用虚构记录与请求拦截：1280×1000、390×844、浅色及深色无横向溢出；设置标题统一 15px、600 字重和主题色。说明弹窗关闭后保留配置草稿；逐字记录折叠、重开保留未保存草稿；关闭时不占一行。
5. 纪要失败提示为 fixed 顶部浮层（top 20px），不含 is-inline，正文位置不变。树形小结背景、说话人和来源按钮正常；不显示原音/转录处理详情行。
