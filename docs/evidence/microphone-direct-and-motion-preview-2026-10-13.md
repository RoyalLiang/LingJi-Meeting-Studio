# 麦克风直接开启与动效待选

日期：2026-10-13。本阶段修复麦克风入口；“当前正在聊”的动效仅提供预览，等待用户选择，不接入客户端。

用户确认弹出的窗口是客户端“音频来源”，并非 macOS 系统权限窗口。已定位 `startCapture`：单音源接入异常和普通会议部分失败都会调用 `setModal('capture')`，因此点击“开启麦克风”会被强制带到设备选择。使用实际 App 函数的最小回归复现两项失败、一项通过；修复后错误通过现有页面反馈直接显示，保留失败音源信息及正在工作的系统音轨。手动打开的来源窗口仍保留，接入成功后正常关闭。

新建控制器已经默认启用麦克风，与系统音频一起启动；默认设备及失效保存 ID 的回退仍由现有设备策略执行。有效的显式设备选择、用户主动关闭麦克风后的暂停恢复、真实权限拒绝和虚拟输入保护继续保留。本轮没有把接入失败伪装为已开启，也没有自动接受系统授权。

定向采集与原生控制器合成回归 40/40。从 HEAD 提取并仅叠加本轮 App 补丁及测试的隔离快照通过 266/266 Node 回归、ESLint、TypeScript 和生产 Web 构建。另一会话未提交的学习功能和 IDE 改动均未纳入。本轮没有打开真实音源或替换客户端；检查时已安装版本为 Alpha12，客户端未运行，未启动它。

三个待选动效为“轻弹三点”“弹性声波”“状态回弹”。预览只移动活动指示或状态标签，外框高度固定，支持减少动态效果和 320px 窄屏。播放由用户触发，有限时长；选择后向当前对话提交明确的方案名称。客户端 `CurrentDiscussion` 和样式尚未更改。
