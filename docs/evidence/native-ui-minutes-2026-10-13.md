# 原生动效、自动提示与纪要延迟验收

日期：2026-10-13；基线 `de64f89`。本轮是 Alpha 8 交付自查后的修订。已有客户端、录音、API 与 worker 不参与测试，未调用真实供应商。

## 界面与原生 WebKit

关闭按钮尺寸为 44px，齿轮自动以 8 秒一圈旋转，中央 20px 关闭符号保持方向；减少动态效果时停止旋转。

使用系统 AppKit/WKWebView 非持久数据仓验证生产组件，避开本机 Playwright 与旧 WebKit 协议不匹配的问题。组件 13 项及最终生产 Web 构建 4 项检查通过。原生验证找出并修复两处问题：鼠标打开 combobox 后显式保留焦点，让 Escape/Tab 能可靠关闭；不支持 overlay 动画的 WebKit 立即收起列表，避免淡出时退出顶层导致弹窗内闪影，仍保留展开动效。

普通操作成功反馈使用 5–10 秒自动 toast，鼠标悬停、焦点、后台或被另一条提示覆盖时暂停；同文重发重新计时并升到顶层，不抢焦点。错误、录音恢复操作和确认保留；复制表格的错误留在原位置。

## 纪要正确性与延迟

新模型输出的主题包含唯一 id，每张表必须完整指向对应主题。后端拒绝缺失、未知或重复归属，仍逐行核对原始片段与 revision；前端按明确归属内嵌整张表，不凭共享引用拆到总体底部。历史与人工编辑仍兼容原格式；无法确认主题的旧表保留可见，重新整理后才产生新归属，不自动重写旧纪要。

主题/引用布局与覆盖时长改用索引，保留原有片段修订和重叠时长口径。长引用默认显示三条，可展开全部并跳到原始修订，减少初始 DOM。

长稿独立分窗与同层汇总默认并发 2，最多 4，可用后端环境 `RECORD_MINUTES_WINDOW_CONCURRENCY=1` 串行回退。保持结果顺序、同窗口调用及计费去重，失败停止派发并排空在途任务。会中最近 120 段按完整转录位置锚定窗口，避免每新增一段导致所有缓存失效；默认 30 秒节流和输出内容范围保持原样。提示词缓存策略升至 2、任务键升至 v3，允许显式重新整理旧产物，人工修订与过期 fence 仍受保护。

| 滚动会中纪要模型调用 | 18 次 | 5 次 |
| 8 窗口+1汇总，每调用注入40ms等待，中位总时长 | 471ms | 267ms |

浏览器每项预热后采样三次；记录计算、同步 React 提交、强制布局和等待下一帧的不同阶段，不把帧相位等待当纯绘制耗时。SQLite/本地 HTTP 及生成等待是合成夹具，以上不能代表真实模型首字、网络耗时或线上总耗时；单窗生成仍需一次供应商调用，并发后的真实限流表现未验证。
