# 会议收尾、导出与两分钟纪要上下文

日期：2026-10-21。源码起点：`e16a838`，分支 `dev_browser-records`。本页记录本地源码、隔离 HTTP 和浏览器验证；没有升级正在使用的 Alpha 客户端，也没有改写真实会议或调用供应商。

## 已实现行为

- 用户确认 A「紧凑同行」。保留固定播放按钮，移除右上方悬浮重置，旁边提供导出入口。
- 结束录音会等待已在执行的上传，并再次检查排空后保存的尾包；完整持久化的封存音轨不等待 ASR 即可回放。首次加载失败后，点击播放会重新加载媒体。
- 导出窗口支持 Markdown 纪要和逐音源 WAV。Markdown 包含已保存的主题、正文、表格、决策、发言人总结、行动候选、人工笔记与冻结版本引用；会中结果标为草稿。完整记录 JSON 备份仍是独立入口。WAV 保留对应来源的 PCM 样本，双音源及暂停后的新时段分别列出。
- 默认会议名在经校验的会中纪要提交时同步，终稿仍可优化自动名称；人工会议名不被覆盖。人工修改纪要标题后，也会同步尚未人工命名的会议。
- 增量纪要回看新片段之前两分钟的确认转录，回填全部未处理片段。已整理片段标记 `contextOnly`，在分窗与分层汇总中保留标记。提示词要求按实际议题变化组织主题，避免依片段、停顿或窗口边界机械分段。
- 有时间戳的输入以两分钟时间桶和字节预算分窗；不人为切断 ASR 原句。未带有效音频时间的文字导入仍按容量分窗。刷新间隔没有改变；直接向纪要 agent 传音频尚未实现。

## 已验证证据

`npm test`：316/316 通过。ESLint、Web 类型检查、Web 构建和本轮文件空白检查通过。构建仍有既存的 bundle 大小和 Tauri 静态/动态导入提示。

故障回归先失败后通过：上传正在运行时结束收尾、默认名跟随会中纪要、媒体初次加载失败后重试。其他回归覆盖两分钟时间窗、模板切换、旧事实上下文标记、分层引用、人工保护、Markdown 冻结原文、中文及特殊字符文件名、缺少纪要、鉴权和 WAV 样本一致性。

隔离 in-app Chromium 使用两路静音 PCM、SQLite/文件与本地 Vite/API。在 `capture=sealed`、40 个音频包均未完成 ASR 时，两路媒体均进入播放，`readyState=4`、`error=null`，时间位置约 0.16 秒。Markdown 和两路 WAV 的下载准备及中文文件名已核对；HTTP 回归核对实际响应内容和 WAV 字节。

1280×900 与 390×844 检查页面宽度等于可视宽度；悬浮重置节点为 0。桌面浅色、深色导出窗口和手机布局截图已检查。隔离证据保存在 `.agent-runtime/meeting-20261021/`，回归日志为 `/tmp/tts-regression-20261021-verified.log`。

## 尚未验证的边界

没有实体麦克风、系统采音、真实长会议、真实模型分段语义质量或更新后原生 WebView 的全流程证明。原生下载完成事件已接入，但新版客户端尚未打包、安装或实机验证。双路和分时段录音导出为独立文件，不合成为单一混音文件。历史已经人工命名的会议不会被批量重命名；已清理的原音无法恢复。

两分钟上下文会增加输入量；超出字节预算时仍拆分和汇总，不能据本地夹具宣称模型质量、延迟或成本改善。
