# v0.1.36 纪要效率、地址与排版本地证据

日期：2026-10-28。基线：`697736672d1b85552ca7dc78492d506f527600d7`（v0.1.35 回执）。本地完成不等于发布成功，最终安装包状态以后续 Actions 与公开附件核验为准。

## 已核实原因和实现

- 旧文本后端直接 POST 配置的 `LLM_API_URL`，没有自动追加协议路径。用户提供服务的最小探针：`GET /v1/models` 为 200 且目标别名存在，`POST /v1` 为 404，`POST /v1/chat/completions` 与 `POST /v1/responses` 均为 200。测试未把真实会议发送到服务，密钥没有写入文件或提交；此处不公开私有服务地址。
- v0.1.36 对无查询参数的根级 `/vN` 补全所选协议路径；完整自定义路径、根地址与查询 URL 保持原行为。专用翻译继承版本基址时也走其 Responses 路由，仍禁止把模型密钥继承给另一专用地址。
- 转录引用在请求中用整数索引表示，历史上下文引用也可往返；来源、说话人、纠错目标使用短别名。模型结果入库前恢复原 ID/revision，再执行既有冻结证据、修订、取消与人工保护校验。负数、越界、错误修订不会被静默修复。
- 文字分窗上界为 5 分钟，音频仍 2 分钟；原载荷预算不增加，自动刷新不等待 5 分钟。保留跨窗模型语义整合，不能以 `corrections=[]` 推断不存在本批撤回。
- 汇总按实际发送的紧凑载荷计算预算。窗口摘要、来源和有预算的原文摘录保留；服务端校验始终使用完整冻结原文。重复 JSON schema/指令精简后，标准 live 提示词由 9400 降至 8771 UTF-8 字节；这不是 token 计数。
- 缓存输入和推理输出是现有输入/输出的子项，重复回报不重复累计总量；未知信息不伪装为零。本轮未自动降低用户推理设置，也未用很小的输出上限截断结果来制造节省。

需有本地 `v0.1.35` 标签。基准使用旧编排和当前领域校验，不是旧二进制应用回放；模型为纯桩，没有网络或费用。

## 真实文字模型短样例

仅发送虚构的三句话：项目甲周五只是候选且被取消，下周一仅复评，负责人和上线日期未确定。Chat Completions 非流式和 Responses 流式均完成生成，恢复引用后通过原有验证；输出保留了取消、复评与未承诺日期的含义。

同一旧短别名探针各一次：auto 输入 2573、输出 1522（其中推理 954）；low 输入 2573、输出 2435（其中推理 1813）。这是随机单次观察，不构成 low 必然更贵或更省的结论，也未核实私有模型别名背后的全部路由策略。

最终整数协议的 Responses 流式探针：输入 2283、输出 1888、总量 4171；缓存输入 2176、推理输出 1375 均已包含在相应总数。不同探针之间的协议、缓存状态与随机输出不同，不作为精确 A/B 节省率。2048/4096 等测试上限曾导致部分探针未返回完整 JSON，这些不完整结果没有入库。
