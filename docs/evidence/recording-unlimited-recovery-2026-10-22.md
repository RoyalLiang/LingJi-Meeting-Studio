# 两小时限制、音源中断与自动发版规则

日期：2026-10-22。范围：本轮源码、回归及已完成的 v0.1.2 后台 Actions 发布。

## 已确认原因与实现

- 用户确认满额提示指“两小时的限制”。v0.1.1 的 `record_duration_limit` 仍限制累计样本，两路音轨合计也消耗配额；后续本地 `f9fbb5d` 已移除，但此前未发布新安装包。本轮 v0.1.2 将包含该变更。当前 bootstrap 返回 `maxMinutes: null`。
- 浏览器此前对音视频全部 track 的 ended 事件直接暂停整场；现在仅处理实际音频轨，先保存尾段，再释放该路。其他音源继续录制。
- 原生控制器此前遇到任一设备故障即停止全部流；现在隔离故障音源，允许新 source/epoch 重接。存储失败仍暂停全部采集，不静默丢弃待传音频。
- 全部音源丢失走 pause 路径，只有用户结束会议才 seal。旧控制器回调不能暂停或修改新会议。
- flush 确认按 worklet 匹配，避免并发音源错配收尾通知；record/session/source/epoch/sequence、持久 ACK、水位与补传规则保持。
- `AGENTS.md` 明确了用户对提交、推送、递增测试版本和后台 Actions 构建发布的持续授权。发布回执补记不循环发包。

## 验证

新增回归先复现四项失败，再修复通过；另增加旧控制器隔离测试。48 项录音定向回归通过，类型检查、ESLint 和 Web 构建通过。最终 369 项 Node 回归、ESLint、类型检查、Web 构建和 111 份 Markdown 文档检查全部通过。

已有三小时双音轨用例检查 1440 个片段及累计六小时样本，重传不重复计量；HTTP bootstrap 检查不再宣传两小时上限。此为合成边界验证，并非六小时实体录音。

本机完整回归首次受沙箱禁止 listen 影响，64 项均为 EPERM；允许本机临时端口后 367 项全部通过，随后加入旧控制器及尾包落盘失败回归，最终 369 项全部通过。

依 code-review 技能对本轮修复按 Standards 与 Spec 两轴只读审查，固定基线 `b117bd0`。Standards 发现尾包落盘失败后仍发“已保存”提示，新增回归复现后修复；最终修复提交 `c1631b7` 经独立复核确认该 P2 关闭。Spec 轴无已证实实质缺陷；真实发版需后续远端证据。

## 发布与未验边界

本轮目标为 `v0.1.2`，macOS Apple Silicon 测试安装包，通过 tag push 自动触发 `preview-release.yml`。实际 verify/build/publish 已全部成功，五附件均完成完整下载和摘要校验，见[发布回执](preview-v0.1.2-2026-10-22.md)。

没有操作用户会议、没有替换当前安装应用。48 MiB 待传保护、64 MiB 单文件导入和其他资源保护仍保留。真实设备连续两小时以上、锁屏/音源拔插、供应商识别与 Realtime 尚未实测，不把合成用例或 CI 包体检查当作这些场景验收。
