# 长会议纪要与连接恢复修复

本轮修复了后台事件流退出、归档弹窗误关闭、断连提示和会中纪要重复处理尾窗的问题。修复阶段完成源码和本地隔离验证，随后已打包 Alpha 17 并通过隔离原生启动与重启恢复检查；未替换运行中的客户端、重启真实后台或重新生成真实会议纪要。

## 已确认的原因

运行中的 Alpha 13 本机后台日志记录了 `ERR_STREAM_WRITE_AFTER_END`，调用点是事件流心跳。该后台子进程已退出，HTTP health 无法连接，而原生页面代理仍在监听。这解释了持续重连，以及打开会议、归档和备份一起失效。右上角指的是页面与 Record API 的连接，和 ASR、AI 模型供应商连接是不同链路。

隔离 HTTP 回归复现了相同异常：事件写入返回背压后结束响应，随后心跳再次写入。修复后等待 `drain` 再发送后续事件，并在响应关闭、报错或异步查询返回后检查生命周期。断连不会再导致这条路径退出后台；事件游标、撤销授权和补历史语义保留。

只读任务元数据显示，一次会中模型调用约 94.9 秒，之后两次调用约 120 秒超时。旧实现每轮只读取最后 120 个片段，且不带历史主题上下文。这是重复处理、早期项目名称逐步离开输入的已确认机制；不能据此把全部延迟归因于客户端。

## 当前源码的行为

- 会中首轮覆盖可用转录；之后输入新增片段与前面两个片段作为指代上下文。累计保留已校验正文、行动及引用，主题使用稳定 ID，并携带最多约 12 KB 的项目记忆。模型提示要求同一项目的现象、根因和安排归入同一主题，跨项目不能仅凭相同设备名称合并。
- 已校验的窗口内容可先显示为“正在更新”的草稿。后续窗口或综合模型仍可运行；草稿在完成前不能人工修订。旧引用修订、笔记修改、人工纪要版本变化、任务取消和生成栅栏仍能阻止迟到结果覆盖。
- 主题摘要、发言人摘要及表格是简短视图；累计事实保存在正文。结构容量与引用校验继续生效，超限不会静默截断正文。
- 归档目标仅列出工作目录，选择目录不关闭弹窗，确认归档后再关闭。已成功写入但刷新失败时，明确提示“已保存”，不把刷新失败当成写入失败。
- API 不可达与事件流中断分开显示。临时断连保留当前和本次浏览中最近八场已读取的会议；权限失效清理对应缓存。未读取的会议仍需记录服务恢复后才能打开，缓存不提供离线写入。
- 公共请求和备份读取失败统一转换为可读错误；未确认的保存响应明确提示结果尚未确认。页面错误使用 toast，备份不再插入漂移的行内错误。处理状态与备份合为紧凑一行。

## 本地验证

使用独立临时 SQLite 数据、隔离 HTTP 端口、合成转录和模型替身，没有外发真实转录或使用业务密钥。289 项 Node 回归、ESLint、TypeScript、Web 构建及 91 份文档检查通过。完整项目检查记录见工作目录 `.agent-runtime/long-minutes-fix/`。

- HTTP 验证：背压等待排空、查询未完成时关闭连接、事件游标重置、授权撤销，以及连接关闭后 health 与会议读取仍可用。
- 长会议验证：160 段初始会议完整覆盖；追加一段后只输入三段，累计快照保留 161 段及早期要点。项目上下文经实际 provider 请求序列化传入，合成的同一项目保持单一主题。修改旧引用使在途增量结果作废。
- 分批显示验证：后续窗口被主动挂起时，首个已校验窗口仍可通过公共记录投影显示；浏览器显示主题、来源及 `1/2` 进度。
- 浏览器验证：下拉选择后归档弹窗仍打开，确认后目录元数据一致；断连切换已读取会议成功，备份只有一个固定位置 toast；恢复后可重新连接。1280×720 下处理区域约 44px 高。

## 验证边界

实际 Alpha 13 的退出原因有日志、进程状态与 health 证据。修复和恢复行为通过源码、隔离 HTTP 与浏览器验证。Alpha 17 安装包的隔离原生启动、保存和重启恢复已通过，见[打包验证](client-meeting-alpha17-2026-10-14.md)。真实供应商在超过 15 分钟会议中的延迟、自然语言项目归类质量，以及原生 WKWebView 的完整会议交互仍未验收。已有真实纪要不会自动重写；本轮没有执行已安装客户端的覆盖安装。
