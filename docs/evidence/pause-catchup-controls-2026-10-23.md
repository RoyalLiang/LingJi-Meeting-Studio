# 暂离纪要补齐、启动提示与播放控件修正

## 用户确认与验收范围

2026-10-23，用户报告每次打开 App 都出现语音处理提示、会议停止后纪要未补全，并要求播放器通过波形点击或拖动定位、去掉右上快速跳转与左下时间、将倍速改为更紧凑的图标操作、移除纪要区两处常驻说明。用户随后确认，停止会议时点击的是“暂离/暂停”。

因此，暂离需要补齐截至暂停时的已录内容并保留恢复能力；真正“结束并整理”仍负责整场终稿。该改动不扩大原音授权，也不自动重送历史失败录音。

基线为 `a782603347a672f72ec3b5b0d809c5d4657f6cdd`，本机已安装 Preview 的 Info.plist 为 0.1.11 / bundle 0.1.33。原始工作目录中的 IDE 和播放器未提交改动保持原样，实现在受管隔离工作树进行。

## 已复现的问题和已排除的假设

- 提示关闭只保存在 React 当前组件中，重开后丢失。现在按会议、故障类型和手动重试版本记住关闭操作；新故障和显式查看入口仍会显示。禁用本机存储时仍可正常关闭当前提示。
- 同一转录版本的会中草稿失败后，原自动调度认为内容没有变化；暂离后不再恢复。新增暂停检查点，等已保存音频排空后立即补齐，失败时按 15 秒、30 秒间隔恢复，最多三次尝试。
- 原终稿的重试白名单没有包含模型 JSON/纪要顶层结构错误。新增有上限的重试，每次结果仍须通过结构与引用校验；未校验内容不会提交，人工内容仍受保护。
- 暂离补齐仍使用两分钟会中预算，流水线续租也会重写回该预算。统一为四分钟请求预算与五分钟租约，并通过第二个 worker 不会在 190 秒时接管在途任务的回归验证；持续录制中的实时更新保持原预算。
- 只读本机元数据中，最近暂离记录的保存音频均已转录，但近期纪要任务存在超时和结构错误。这支持继续恢复整理，不能据此断言所有供应商超时都来自客户端。
- 旧 ASR 配额失败在切换音频模型后仍要求手动重试，这是已有的历史录音保护。最初的模式迁移复现经现有回归核对后，被确认为应保留的行为；未将它改成自动重送历史音频。

## 本地验证

暂停及结束两种场景均验证了：模型返回不完整内容、只保存失败状态、关闭并重新打开仓库、自动重试、提交有效纪要、相同内容不再重复请求。暂离过程中 capture 仍为 paused。

播放器组件测试覆盖真实波形展示、点击定位、拖动时不反复 seek、释放后双轨统一定位、短轨结束位置、统一倍速和音高保持。右上跳转框与左下时间节点均已移除。

完整 Node 回归、类型、构建、原生窗口、独立评审和后台发布证据继续补记。本文件不保存用户会议正文、密钥或原始数据库内容。

升级恢复回归另确认：旧失败记录的持久化 nextWorkAt 可能仍指向旧调度。启动时仅重算比既有截止更早的暂停/终稿恢复任务，不重写无变化的历史。独立复核补上点击波形后的键盘焦点，并明确滑块覆盖整个波形高度。

完整 Node 回归 421 项、发布/原生配置 27 项、lint、类型检查、Web 构建与 139 份文档引用检查通过。另用真实 SQLite 文件的合成记录验证旧未来期限被提前重算，重开数据库后仍保留，见[SQLite 落盘核验](pause-catchup-controls-2026-10-23/startup-sqlite.json)。这项独立探针补足启动单测中 repo stub 的持久化边界。

独立复核还覆盖停止清单尾包：第 0 包已转录，pause 清单声明第 1 包但尚未补传时，不得生成检查点；第 1 包持久确认后仍需等待转录提交，随后才允许补齐。已补实际 pause/acknowledge/commitTranscript 路径的红绿回归。

本轮原生调试 App 已构建，并以唯一应用标识、独立目录及合成音频启动；Mac 锁屏导致 CUA 无法读取窗口，因此尚未把原生点击/拖动、实际尺寸或浅深色截图计为通过。未使用浏览器作为替代，未访问真实设备或云端供应商。后台发布检查与该界面验证层分别记录。
