# 产品需求文档 v1

- 文档状态：`Draft`
- 更新时间：`2026-03-19`
- 产品代号：`TTS Platform`

## 1. 问题定义

现有语音转录工具通常只解决“把声音转成文字”，但真实用户要解决的是：

- 会议过程中听不清、跟不上、跨语言理解困难
- 专业术语识别差，导致 transcript 可读性和可信度不足
- 参会者无法把实时内容分享给旁听者或异地协作者
- 会后复盘耗时，纪要和行动项需要人工二次整理

因此，`v1` 要做的不是单点转录，而是一个围绕实时会话构建的语言协作产品。

## 2. 产品愿景

让用户在任何重要会话中都能：

- 实时看到可信的转录结果
- 在需要时即时翻译
- 把关键内容安全地分享给他人
- 在会后快速得到结构化纪要与可检索记录

## 3. 目标用户

### 核心用户

- 跨语言会议参与者
- 讲座、培训、采访、用户访谈记录者
- 需要实时字幕辅助理解的用户
- 需要将内容广播给外部旁听者的组织者

### 早期优先细分

`v1` 优先服务两类用户：

1. 使用 `Zoom / Teams / Google Meet` 的知识工作者
2. 需要中英双语实时辅助的会议与培训场景

## 4. Jobs To Be Done

### 主任务

- 当会议正在进行时，我想低延迟地看到实时文字，这样我能跟上讨论。
- 当出现外语内容时，我想立刻看到翻译结果，这样我能继续参与。
- 当术语很多时，我想让系统学习我的词汇和材料，这样 transcript 不会一团糟。
- 当别人无法入会时，我想发一个安全的共享链接，这样他们仍能同步看到内容。
- 当会议结束后，我想直接拿到纪要、行动项和可搜索记录，这样我不必重复整理。

## 5. 北极星指标与成功标准

## 北极星指标

- `Weekly successful live sessions`

## 一级指标

- `Session start success rate >= 95%`
- `P95 partial transcript latency <= 800ms`
- `P95 final transcript latency <= 2.5s`
- `Domain term hit rate >= 85%`，基于内部术语样本集
- `Live Share viewer join success >= 98%`
- `AI notes acceptance rate >= 70%`，由试点用户判定可直接复用

## 6. 版本策略

### P0：必须打透

- Windows 桌面端采集
- 麦克风与系统音频接入
- 单语实时转录
- 中英实时翻译
- transcript 保存与回放
- 浮动字幕
- Live Share viewer
- 基础术语表
- AI 纪要与行动项

### P1：紧随其后

- 多语言目标翻译 fan-out
- 参考文档增强
- AI Chat 基于 transcript 问答
- 共享工作区与文件夹
- 分享链接过期与权限策略

### P2：暂不进入 v1

- iOS / Android 原生客户端
- 完整多租户企业管理后台
- 自研 ASR 模型训练平台
- 复杂 speaker diarization 编辑器

## 7. 功能需求

## FR-01 会话启动

- 用户可以选择音频输入源。
- 用户可以创建实时会话并看到连接状态。
- 系统必须在启动前明确提示录制和转录告知。

## FR-02 实时转录

- 系统必须支持流式 partial transcript。
- 系统必须在结果稳定后提交 final transcript。
- 每个 segment 必须带有时间戳、语言、置信度和顺序标识。

## FR-03 实时翻译

- 用户可以为当前会话选择目标语言。
- 翻译结果必须与原始 segment 对齐。
- 用户可以关闭或切换翻译目标语言而不中断会话。

## FR-04 术语与参考资料

- 用户可以为工作区或文件夹上传 glossary。
- 用户可以给会话绑定参考文档。
- 转录和翻译链路必须可读取相关术语上下文。

## FR-05 Live Share

- 主持人可以生成 viewer 链接。
- viewer 可以看到当前 transcript、翻译与历史滚动结果。
- viewer 无法修改源 transcript。

## FR-06 会后产物

- 会话结束后自动生成摘要、行动项和主题分段。
- 用户可以按时间戳回放 transcript。
- 用户可以全文检索历史会话。

## FR-07 权限与保留

- 用户可以配置 transcript 保留策略。
- 默认不长期保留原始音频。
- 分享链接必须支持过期时间和撤销。

## 8. 非功能需求

- 实时链路可观测，包含延迟、丢包、provider 错误、重连次数
- 关键路径具备断线恢复策略
- 会话数据具备审计日志
- 文本、术语、分享权限具备明确 owner 和边界

## 9. 非目标

- 不承诺一次性支持所有会议软件
- 不承诺离线本地全功能推理
- 不承诺 v1 就达到所有行业的专业转录准确率

## 10. 风险与取舍

- 最大风险不是“模型不够强”，而是采集链路和实时体验不稳
- 过早做太多平台会拖慢主链路验证
- AI 纪要在 transcript 不稳定时会放大错误
- 涉及录音与分享时，隐私和 consent 设计不能后补

## 11. Beta 验收标准

满足以下条件可进入受限 Beta：

1. 连续 30 分钟会议可稳定运行
2. 真实会议中 `P95 partial latency` 达标
3. 中英双语翻译可用且不明显拖慢主链路
4. viewer 可中途加入并自动补历史
5. 会后纪要可被试点用户直接复用

## 12. 当前开放问题

1. `v1` 是否存储原始音频，还是仅在用户显式开启时存储
2. glossary 的输入格式优先支持 CSV、TXT 还是结构化术语库
3. Live Share viewer 是否要求登录，还是默认匿名只读
4. AI Chat 是否在 `v1` 一并上线，还是放入 `v1.1`
