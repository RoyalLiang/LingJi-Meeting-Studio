# 会议纪要 token 效率：压缩重复结构，保留语义汇总

研究日期：2026-10-28。范围：现有增量转录、历史上下文、两分钟窗口与分层汇总链路。研究作者仅查一手资料、本地代码及本轮实施代理回传的验证结果，没有访问内部模型网关、读取密钥、读取私人测试文件或独立调用付费 API。下述本轮验证数字为回传记录，本研究未独立重跑。

**本轮压缩重复引用和标识、精简稳定输出指令，并增加用量细分；完整保留原有跨窗口语义汇总。** 不截断转录、不删除条件/否定/撤回，也不放松引用校验和人工编辑保护。用户报告“约 50 分钟使用 40 万 token”是待核对的实际观察，不是本研究独立复测，也不能仅凭该数字推断存在重复记账。

## 1. 先区分三个数字

| 指标 | 正确解释 | 对优化的意义 |
| --- | --- | --- |
| 供应商 token 总数 | DeepSeek 定义 `total_tokens = prompt_tokens + completion_tokens`；输入包括命中和未命中缓存部分 | 缓存命中后的输入仍属于 token 使用，不能从总数直接扣掉 |
| 缓存计费 | 命中输入和未命中输入价格不同；不是零 token，也不是零费用 | 缓存可以降成本/重复前缀计算，但不保证面板 token 数明显下降 |
| 推理 token | `completion_tokens_details.reasoning_tokens` 是输出用量细分，不能再加到 completion/total 上 | 用户看见的纪要正文很短，输出用量仍可能包含未显示的思考；只记录数值，不记录思考正文 |

一手依据：[DeepSeek Chat API 的 usage 定义](https://api-docs.deepseek.com/api/create-chat-completion/)、[缓存命中字段](https://api-docs.deepseek.com/guides/kv_cache/)、[输入缓存命中/未命中和输出的计价分类](https://api-docs.deepseek.com/quick_start/pricing/)。本文不固定价格，实际费用按调用渠道、模型、时间及账单核对。

原基线 [`tokenUsage`](../../packages/records/src/usage.mjs) 只规范化输入、输出和总量三项。本轮增加缓存输入、推理输出的数值明细，不重复计入总量，不保存思考正文。完整成本诊断仍应按每次上游请求核对 stage、实际模型 ID、可用 usage、重试与完成状态；缺字段保持未知，失败或迟到请求已消耗的用量仍需计入。

## 2. 本轮最小改动与安全边界

**请求内整数引用与短别名。** 原转录、版本和证据关系不变，单次模型请求将重复证据引用表示为整数，并给来源、说话人和纠错 target 使用短别名；映射包括历史 context 的旧引用。服务器返回边界先还原原 ID＋revision，再走原有结构、引用和版本校验；未知或冲突的引用拒绝，不能猜测。持久化继续使用真实标识，缓存绑定真实内容、版本和策略。另精简稳定输出指令，减少重复格式说明，不删正文或语义约束。

**不跳过跨窗口语义汇总。** 独立审查已复现：即使各窗口没有显式 `corrections`，本批次后窗也可能撤回前窗结论，结构和引用校验通过不能证明语义一致。此前“正常会中结果确定性合并即可省一次模型调用”的建议已撤回，本轮对应 shortcut 已删除。会中与终稿继续原有跨窗口语义汇总，终稿按完整冻结版本整合；不能用结构合法的拼接替代更正、撤回和条件关系的整合。

本轮回传的等价 payload 检查使用 50 分钟、300 片段的合成场景，全部正文和引用往返一致：

| 比较项 | 优化前 UTF-8 字节 | 优化后 UTF-8 字节 |
| --- | ---: | ---: |
| 等价输入 payload | 176153 | 127033 |
| 等价输出 payload | 67786 | 49076 |

这是结构压缩的确定性字节证据，**不是供应商 token 实测**，也不代表真实 50 分钟会议的总调用消耗。实现及验证结果以本轮代码/验收记录为准。所有权、缓存和汇总依据见[纪要流水线](../../services/records/src/minutes-pipeline.mjs)、[增量上下文与合并](../../packages/records/src/live-minutes.mjs)、[供应商 JSON 调用与校验](../../services/records/src/providers.mjs)。研究作者没有改动这些文件。

## 3. 缓存：稳定前缀有用，但不为命中重发无关内容

**DeepSeek 官方上下文缓存**默认启用，复用已持久化、完全匹配的前缀单元；命中为 best effort，不能保证。适合将固定系统规则/结构定义放在稳定前部，动态转录和不断变化的上下文放后面；避免无关时间戳或随机 ID 使共同前缀提前分叉。不要为了缓存把全部旧转录再次发送；新增内容改变后仍需正确生成新结果。[官方缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)。

**LiteLLM 响应缓存**复用完整响应，exact-match 缓存按完整请求匹配；会议新增转录或版本变化通常是 miss。语义近似缓存不是证据版本缓存，不能用“相似会议”响应替代当前人名、金额、否定或新修订。现有窗口缓存应继续以内容/版本/模型策略精确匹配，且隔离 owner/record、笔记与人工修订。[LiteLLM 官方缓存说明](https://docs.litellm.ai/docs/proxy/caching)。

**路由与重试**还需单独核对。LiteLLM 支持 cooldown、fallback 和 retries；客户端重试与网关重试并存时，产品的一次业务请求可能对应多次上游尝试。应核对实际部署配置，不能假设所有失败都不收费。官方 cache-aware routing 针对自托管 Kubernetes 推理 pod 提供会话亲和，推理端还须自己启用前缀缓存，且不保证命中；不能据此断言当前第三方路由具备同样能力。[路由/重试](https://docs.litellm.ai/docs/routing)、[Cache-Aware Routing 适用范围](https://docs.litellm.ai/docs/proxy/cache_aware_routing)。

## 4. 思考模式：分阶段比较，不盲改模型参数

DeepSeek 当前官方文档提供思考开关与 effort 控制，且模型/接口间参数及映射会变化；无 tools 的普通会话不需要把旧 `reasoning_content` 作为下一轮材料。产品应仅使用输出正文和结构化结果，不回显、持久保存或重复发送思考文本。[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。

本轮另有一次真实供应商的虚构短会议对照回传，auto 与 low 均返回完整 JSON：

| 设置 | 输入 token | 输出 token（含推理） | 其中推理 token |
| --- | ---: | ---: | ---: |
| auto | 2573 | 1522 | 954 |
| low | 2573 | 2435 | 1813 |

这只是各一次的随机观察，不构成思考档位优劣或稳定节省的统计结论；本次 low 反而产生更多输出/推理，说明不能保证“low 更省”。本轮不自动降低用户推理设置。后续若比较档位，应在同一冻结会议集重复对照质量、用量和延迟，且参数必须匹配**实际 provider、模型版本与协议**。官方新模型默认值不能证明内部 LiteLLM 别名或旧模型也如此，网关还可能丢弃不支持的参数。单纯降低 `max_tokens` 可能把思考/正文挤到截断而导致失败重试，不能当作质量无损优化。

## 5. 最小验收与结论限度

用同一冻结转录与笔记比较优化前后，至少包含条件决定、否定/撤回、跨窗口更正、重复/同名说话人、人工编辑、混合语言和长会话终稿。先验证整数引用、历史 context 与短别名往返一致、未知引用拒绝、过期结果不回写，再人工比较事实完整性、条件/数字/责任人、主题连续性与证据定位。没有新增转录不发新会中调用；新增内容仍保留必要语义汇总，不以缺少 `corrections` 为跳过依据。

成本报告分列上游调用数、各 stage 输入/输出/推理 token、缓存命中/未命中、失败重试与实际费用；每场总量和每分钟总量都保留。离线字节缩减可作为确定性证据，真实长会议 token、延迟、缓存命中和纪要质量仍要用实际配置对照；不能据短会议单次观察或用户的 40 万报告预先承诺降低百分比。

本研究未独立执行付费 A/B、读取内部路由配置或核对账单；尚不能确认 40 万 token 的来源占比、真实长会议可节省比例或缓存计费收益。

实现补充：文字分窗上界改5分钟、音频仍2分钟且自动刷新间隔不变；汇总按实际紧凑载荷预算。完整流程与验证边界见[配置说明](../engineering/minutes-efficiency.md)。
