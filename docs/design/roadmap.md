## 首批可拆任务

以下是待发布到 GitHub Issues 的任务草稿。用户尚未提供仓库地址，本轮未创建远程工单。

1. **Web 采集能力探测**：输入实际 audio track、音量与轨道结束；产出来源选择和退路；验收真实浏览器矩阵。
2. **音频输入幂等及持久回执**：稳定身份/hash、不可变对象、DB 回执、缺口与连续 ACK；验收 ACK 丢失和崩溃恢复。
3. **转录提交和事件重放**：唯一写入权、版本、outbox、cursor、snapshot watermark；验收重连重复和游标失效。
4. **停止与排空协议**：seal/manifest、范围内补传、provider drain、completeness；验收先 seal 后补块及尾部 final。
5. **纪要 worker**：快照、模板、任务租约、引用校验、stale、人工版本；验收重复/迟到作业及纠错并发。
6. **产品隐私与删除链路**：分开处理许可和留存、TTL、tombstone/fencing、分享撤销；验收旧任务不复活与缓存失效。
7. **Web 状态整理**：渐进建立 React/TS/Vite 外壳与体验 facade，优先来源/录制/保存状态；每个切片保留当前功能对照，不同时重写后端。

1 与协议设计可以并行准备；5 依赖已封存版本语义，分享依赖权限与事件失效，UI 功能切片使用协议 adapter。真正的并行实施需另行确定 owner 与范围。

## 用数据决定后续技术变化

- **是否引入 WebSocket**：HTTP 分块实测请求开销、延迟或背压成为瓶颈时，做同音频/并发的对照；共享幂等与持久 ACK 语义。
- **是否采用 Go**：只有 profiling 显示特定瓶颈，且 Go 通过同协议/恢复契约、兼容与成本测试，才替换对应实现。实验目录存在不是迁移理由。
- **是否做原生端/扩展**：首版目标人群的关键声音来源确实无法通过 Web 覆盖，并且愿意安装时，再做限定能力原型。
- **是否用 GraphRAG**：跨会议问题集显示全文/向量方法不足且图关系带来可复现收益时再引入；先解决来源可信与更新/删除。
- **是否做自动行动**：用户先能高质量确认候选，再建立目的地授权、幂等执行、预览和撤销/补偿。
