# 全屏与后台处理优化（v0.2.6）

日期：2026-10-31。基线 v0.2.5 / 30d9990，发布回执 84e8705。用户追加三个要求，并确认会中刷新与会后收尾都慢。

## 验收范围

1. 应用容器随窗口增宽，保留桌面16px边距及现有窄屏布局，不再卡在1720px。1920→2560视口时，容器宽度同步增长640px，无横向溢出。
2. 重点速览移除独立的“下一步”区域；不删除纪要行动数据、正式纪要或导出中的行动候选。重点、待核实、历史和标题更新继续保留。
3. 减少会中快照校验的重复历史扫描。引用与转录revision匹配、人工修订保护、任务fence和新增转录兼容语义保持不变。
4. 最终汇总开始时立即上报 synthesis，不能等模型返回后才切换阶段；节点4/4不表示整个任务完成。收尾文案明确区分尾段、排队、节点整理和终稿汇总。
5. 收尾提示在会议标题容器内可换行，桌面与窄屏不被省略号隐藏；处理中的颜色与录音状态区分。完成或真实失败后退出处理态。

## 证据与限制

采用实际领域函数、纪要流水线与UI组件；只用合成转录，不连接真实模型。固定600段合成回归测量源ID读取次数，避免把本机用时或模型mock宣称成真实服务提速。现有worker有记录并发和分窗并发，不直接提高其上限，不跨live/final上下文复用模型输出。

完整源码检查、独立 Standards/Spec 评审及三平台发布结果另记。浏览器验证可证明CSS与组件在指定视口下的行为，不替代真实Windows窗口/显卡验收。v0.2.5已发布并整包校验；此追加版须使用新标签，不能改写已发布附件。
