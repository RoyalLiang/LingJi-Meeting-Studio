## 体检发现与整改顺序

`已复现` 表示本次执行了合成探针；`静态明确` 表示触发与行为可直接从当前调用链确认；`待测风险` 不等于用户现场已经卡顿或丢失数据。P1 表示相关 Beta 能力开放前必须解决，P2 表示进入 Beta 验收清单。

### BETA-01 · P1 · 反向代理把登录限流合并为同一个桶

**静态明确，公网鉴权问题。** [server.mjs](../../services/records/src/server.mjs) 91–98 行按 `req.socket.remoteAddress` 计算每分钟 20 次登录/注册请求；[production-server.mjs](../../apps/web/src/production-server.mjs) 9–13 行又将全部 `/api/` 请求代理到同一后端。经过该代理的访问会使用代理套接字地址，同一窗口内不同用户会相互消耗额度。同步 `scryptSync` 还会阻塞 API 事件循环；本次 10 次并发失败登录使零延迟计时器延后约 230 ms。

最小整改：密码算法与历史哈希保持兼容，改用异步派生并限制并发；明确可信代理链，在边缘/服务端实施有边界的限流。不能直接信任任意来访者提供的 `X-Forwarded-For`。验证需经过真实部署代理，覆盖不同用户、同一来源暴力请求、伪造转发头和录音上传同时进行。

### BETA-02 · P1 · 匿名分享请求读取全部会议

**静态明确，公网性能与滥用风险。** [server.mjs](../../services/records/src/server.mjs) 100–105 行在鉴权前调用 `repo.list()`，再匹配分享 hash；[repository.mjs](../../services/records/src/repository.mjs) 113–117 行返回全部记录聚合。错误令牌同样会触发全量读取、解码和遍历，成本随全体会议体积增长。没有发现该响应直接泄露未分享字段，但公开入口可以放大资源消耗。

最小整改：用 token hash 的唯一索引直接定位分享元数据，再读取允许的内容；无效请求限流；为单用户/单记录的有效链接数及过期清理设置上限。现有 `r.shares.push()` 没有数量限制，也需要一起收口。验证 10、1000、10000 条分享数据下的查询计划、无效令牌、撤销、到期与租户隔离。

### BETA-03 · P1 · 长会议的无变化事务仍同步处理整份聚合

**已复现，性能问题；现场卡顿影响待测。** [repository.mjs](../../services/records/src/repository.mjs) 80–96、159–178 行解码整份聚合，对比前后 JSON，并构造可见快照；实际变更时再序列化、压缩和更新投影。已有“无变化不写盘”保护，但仍承担计算成本。

本机 Node 24.21.0、SQLite、压缩聚合、每档 10 次顺序操作：

| 合成数据 | JSON 体积 | 无变化 `repo.change` 中位 | 最大值 |
| --- | --- | --- | --- |
| 空会议 | 881 B | 0.04 ms | 0.31 ms |
| 2000 段转录、8400 个已完成块元数据 | 2,836,740 B | 22.95 ms | 25.68 ms |

这只测仓储计算，未包含真实音频读取、模型或 Windows WebView2。最小整改先避免各 lane 对明显无任务记录进入 `change`，复用轻量工作投影；再按测量结果决定是否拆出 chunk/job 表。保留事务、revision 和 fence，不能把压缩移到事务外后写回过期快照。验证双路 70 分钟与 3 小时合成记录的 ACK 延迟、事件循环延迟和真实写入量。

### BETA-04 · P2 · 打开历史后全文计算和节点数量仍随会议增长

**静态明确的复杂度，卡顿待测。** [Transcript.tsx](../../apps/web/src/components/Transcript.tsx) 12–18 行打开后保留挂载，以保护编辑草稿；28–42 行每次渲染复制排序、清洗搜索并渲染全部片段，逐段再扫描主题引用。关闭折叠区也不会卸载已打开的内容。现有 3000 段测试证明首次关闭时仅渲染摘要，不能证明打开、搜索或持续更新时流畅。

最小整改：按片段/主题修订缓存派生数据，建立引用索引，再按实测决定分批呈现或窗口化。保留未保存编辑、搜索、引用定位、焦点与辅助技术访问。验收需要打开历史后的 3000/10000 段、持续草稿更新、搜索、折叠、恢复编辑和跳转原文。

### BETA-05 · P2 · 周期查询仍有放大路径

**静态明确，容量影响待测。** [server.mjs](../../services/records/src/server.mjs) 250–291 行每个 SSE 连接每 100 ms 验证账户并查 feed；空闲时每连接最多约 10 次轮询/秒。已有 busy/背压保护，但多个连接订阅同一记录仍各自查询。[worker.mjs](../../services/records/src/worker.mjs) 215–225 行及 [desktop-backend.mjs](../../services/records/src/desktop-backend.mjs) 113–119 行有独立 lane 周期查询；仓储已有 due 索引，不能称为全库无索引轮询。

[App.tsx](../../apps/web/src/App.tsx) 79–90 行共享阅读页每 15 秒重新读取，无可见性退避，也不区分静态快照与持续更新内容。最小整改：服务端同记录共享查询/提交唤醒，保留轮询兜底；worker 按 lane 只领取相关任务并空闲退避。快照阅读不持续刷新内容；撤销/到期状态在可见页面有限频率复核，并在恢复可见时复核，立即清除已失效的可见内容。已下载或被接收者另存的内容无法收回。

`listWork LIMIT 100` 未明确公平排序是待测风险：持续就绪记录超过 100 时，需用混合工作队列测试确认是否发生饥饿；本次没有复现饥饿。

### BETA-06 · P1 · 标题截断破坏补充平面字符

**已复现，局部文本完整性问题。** [record.mjs](../../packages/records/src/record.mjs) 25–26 行对标题使用 UTF-16 `slice(0,160)`；159 个 ASCII 字符加 `😀` 后，会只留下高代理项，UTF-8 编码后变为 `�`。服务端标题更新同样使用 `slice`；HTML 文件名也有类似边界。该证据针对截断路径，不表示整段转录普遍乱码。

最小整改：用户可见截断按字素边界；传输体积按 UTF-8 bytes；原始证据及修订不能静默规范化。验证组合附加符、emoji 家庭序列、生僻汉字和边界长度的录入、持久化、分享及导出往返。

### BETA-07 · P2 · 非法多字节签名会进入服务端内部错误

**已复现，异常输入健壮性问题。** [auth.mjs](../../services/records/src/auth.mjs) 6 行先比较 JS 字符串长度，再调用要求等字节长度的 `timingSafeEqual`。64 个多字节字符组成的伪造签名可通过第一层长度判断，但抛出 `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`，HTTP 捕获路径返回内部错误。没有观察到登录绕过。

最小整改：先验证签名编码和长度，再进行等长 Buffer 的常量时间比较；对非法 Cookie/CSRF 返回认证失败。补充中文、组合字符、超长与截断输入回归。

### BETA-08 · P2 · 云端部署边界尚未形成

**实现差距，不是现有离线功能故障。** [share-content.ts](../../apps/web/src/share-content.ts) 9–14 行禁用本地账户及回环来源的 URL 分享；[ShareDialog.tsx](../../apps/web/src/components/ShareDialog.tsx) 生成的是当前 origin 链接。桌面本地账户无法仅靠更换 URL 让外部访问到本机数据。仓库本次范围未找到 Wrangler/Cloudflare 部署配置，现有根页面是工作台入口。

最小整改：新增范围受控的“发布共享内容”能力和官网入口；本地账户与云端发布身份分别处理。不能暴露本地 API、复用本机会话 secret，或默认上传整场会议和原音。

### BETA-09 · P2 · 桌面启动没有独立 Realtime 音频 lane

**静态明确的接线差距，产品预期待核对。** [desktop-backend.mjs](../../services/records/src/desktop-backend.mjs) 113 行启动的六个 lane 不含 `realtime`；独立服务器 worker 则有此 lane。[realtime-minutes.mjs](../../services/records/src/realtime-minutes.mjs) 的持续音频预送与连接协调仅由 `runCycle` 的 `realtime/all` 分支调用。现有 Realtime 回归显式指定 `lane:'realtime'`，不证明桌面实际启动了它。

反证已核对：`generateRealtimeMinutes` 会在纪要任务执行时自行发送对应音频，因此不能将此问题写成“桌面完全不生成音频纪要”。需要明确桌面模式预期是持续预送还是按整理窗口发送，再补实际启动 roster 的集成检查；若要求持续预送，补齐启动与停止关闭，验证不重复发送、不增加无授权调用，并测首字延迟与成本。

## 领域与封装：先修边界，不重写产品

已存在清晰的 Record、Session、Source、Transcript Revision、Minutes Revision 与事件 cursor。需要统一的是调用契约和状态表达，而不是再建立一套名称不同的对象。

- 补齐“共享内容、分享链接、内容快照”的词义，见 [CONTEXT.md](../../CONTEXT.md)。链接是访问授权，快照是某一时点的内容，二者分别有生命周期。
- 将 `RecordDetail.capture`、`transcription`、`Job.status` 等宽泛字符串收紧为已支持状态；新事件与 API 边界有明确结构校验。未知旧版本如何显示也要有兼容策略。
- 在现有仓储内增加分享索引、工作投影查询等深接口；不让 HTTP/界面重建聚合内部状态。只有压测证明整份聚合无法满足目标时，再拆持久化结构并设计迁移/回退。
- `server.mjs`、`Workspace` 与 worker lane 的职责多是维护风险，尚不足以证明要重写。每次整改沿调用链抽取一处共同逻辑，保留错误处理和校验。

## Cloudflare 官网与会议 URL 的建议方案

架构状态为 proposed，取舍见 [ADR 0017](../adr/0017-beta-public-sharing.md)。官网和只读分享优先部署到 Cloudflare Workers Static Assets；分享元数据使用 D1，内容快照放私有 R2，通过 Worker 校验访问。已有 Node/SQLite/原生 ASR 保持原运行边界。

Cloudflare 官方支持静态资产与 Worker 一起部署，并可按路径优先执行 Worker；因此官网静态内容和受控分享接口可以使用同一部署管线。[Static Assets](https://developers.cloudflare.com/workers/static-assets/)

Workers 的文件系统是内存型 VFS，临时文件不是现有 SQLite/磁盘音频的持久存储替代；不能把完整 Record 服务直接打包上传后就视为迁移完成。[Workers fs](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/)

### 最小用户流程

1. 官网展示产品说明、平台下载、使用边界、帮助与反馈；示例纪要仅使用虚构数据。
2. 会议中或会后选择“发布分享”，先预览范围与版本；草稿有明确标识。默认仅纪要及引用原文，全部转录需另选，首轮不分享原音。
3. 通过独立云端发布身份完成认证后，发送有版本的结构化共享内容；服务端重新校验、按白名单投影并生成受信模板。禁止把任意上传 HTML 当成同站点可执行页面。
4. 返回 `https://<已确认域名>/share/<不可猜测令牌>`。接收者无需安装，打开即可阅读表格、纪要和引用；离线 HTML 导出继续保留。
5. 发布者可撤销，或显式重新发布新版本。首轮建议沿用 24 小时默认有效期；快照不会因后台纪要重生成而悄悄扩大内容。

### 数据、权限和失效条件

- D1 的 token hash 唯一索引直接定位 `Share`；记录发布者、快照版本、范围、到期/撤销时间与幂等请求标识。D1 支持 Worker 绑定上的参数化查询。[Prepared statements](https://developers.cloudflare.com/d1/worker-api/prepared-statements/)
- R2 仅保存允许发布的内容快照；先写对象，再提交引用；失败对象按宽限期清理。R2 默认私有，读取走 Worker 绑定。[R2 访问](https://developers.cloudflare.com/r2/api/workers/workers-api-usage/)、[公开访问边界](https://developers.cloudflare.com/r2/buckets/public-buckets/)
- `/share/*` 与相关读取接口必须经过 Worker 的过期/撤销校验，不得被 SPA fallback 或静态缓存绕过。敏感页面和数据使用 `no-store`、`no-referrer`、`noindex`、严格 CSP；关闭 R2 直接公开入口，日志脱敏令牌。
- 云端发布身份首轮采用邀请制。身份提供方、桌面授权回调和发布权限撤销方式需在实现设计阶段冻结；它是本地数据真正可公开分享的前置条件，不能在客户端嵌入统一写入密钥。
- 删除本地会议需要说明是否同时撤销已发布快照：建议默认排队撤销关联链接，离线时显示待撤销；“立即撤销完成”必须等服务端确认。不能暗示已收回接收者下载的文件。
- 官网静态内容可缓存；私人分享正文不能套用官网缓存策略。所有权、有效期与范围由服务端判断。

发布所需但本轮未知：Cloudflare 账户/Zone、正式域名、部署权限、云端发布身份方案、试点规模与费用上限。本次未读取或要求用户粘贴凭据，也未修改 DNS。实施时通过受控后台凭据与 GitHub Actions 部署，预览环境先验收，再切正式域名。

## 专名识别词库：减少人名和场景名的转录错误

**已确认的用户目标。** 用户在本任务中澄清：“避免转录错误，比如常见人名，场景名”。本工作包统一称为“通用识别词库与场景词表”，目标是提高专名识别与纠错质量。BETA-06 的 Unicode 截断仍是独立的数据完整性缺陷，不代替词库建设，也不扩大为全球字体工程。

| 识别后纠错 | 明确 alias 可在最近 120 段找候选；模型检查由人触发，最多 20 段/16000 字符；确认时核对片段修订并保留识别原文 | 补同音/近音候选、来源/理由及上下文排序；保留人工确认、版本校验和人工编辑保护，长会议分窗处理且显示已检查范围 |

现有功能、限制及证据见[多语种与词表说明](../engineering/multilingual-vocabulary.md)。上面的接口参数是本次固定代码基线的事实，不保证外部服务的实际识别增益。

### 最小落地顺序

1. **固定一个小型公共基包，复用私人词表。** 公共包只含已核对来源的必要读音/常用词与经筛选的场景词条，记录版本、适用语言、来源和许可。先使用固定版本，不先建立通用词库下载平台。人名的正确写法优先来自用户明确维护的私人名称集；公共常见姓名库不能推断本场人的真实姓名。
2. **按本场上下文择词。** 私人名称、目录/项目场景词和标题、笔记、近期发言共同限定候选。公共高频词不能压过有依据的专名；同名、同音但都合法时保留歧义。支持热词的识别端只接收预算内相关词，识别提示与云端模型校对分别说明外发范围。
3. **补读音候选，复用确认入口。** 先为已有词条建立有界读音索引，再按需检索公共基包；支持多音姓氏和用户指定读音，保留词边界和语言范围，避免对整句展开所有读音组合。生成带片段位置、revision、来源、理由和上下文的建议，人工确认后再修订；不能做同音全局替换。
4. **确认经验只在选定范围复用。** 用户确认某个错误写法后，可显式选择加入本人或当前目录词表，后续会议复用。一次确认不等于对所有同音文本永久替换；不得自动把私人名称上传公共包或加入其他账户词库。

例如“王小明”和“王晓明”可能都是正确姓名：若本场词表与上下文有足够依据，可以提示后者；只凭公共词频不能自动改写。该例是虚构测试用例，不是实际参会者资料。

公共字音、词级数据与下载更新的候选方案见[已有词库研究](../research/network-offline-vocabulary-2026-10-28.md)。它仍是研究材料：最终具体文件/版本的许可、数据质量和包大小需要在实施时核对；本轮没有下载或重新分发数据包。先验证小基包的实际增益，再决定场景扩充和在线查询，在线查词不进入每段实时识别关键路径。

### 用专名效果验收，不能只看词条数

使用经许可的固定音频、人工金标准和相同模型设置，对比“无词表、现有私人词表、加入通用/场景词库”。分别评估本地 SenseVoice 与实际使用的云端 ASR：

- **识别时的效果：** 按人名、地点/场景名、业务术语分别计算完整词形命中率，并记录漏识别和错识别；该指标只看人工修订前的 ASR 输出。
- **识别后的效果：** 单独记录候选召回、人工审核误报，以及确认后文本的正确率；不将人工修订后的成绩混入首遍识别成绩。
- **反例与保护：** 同音合法姓名、多音姓氏、新名称、中英型号、噪声、否定句和没有相关词条的会议；原本正确的内容不能被高频词错误替换。保留识别原文、片段 revision、既有纪要冻结引用和人工编辑。
- **运行成本：** 冷启动、单段候选耗时、索引内存、模型调用次数和 token；词库损坏或不可用时保留原始转录并显式显示词库状态，不能阻断录音或静默改写原文。
- **隐私与长会议：** 账户/目录隔离、已处理范围、模型校对的单独触发与外发告知，以及词表更新/删除后的候选失效。

首轮先采集基线，再冻结改善幅度与可接受误报门槛。本轮没有专名标注音频集或真实会议对照实验，因此只确认代码基础和待做工作，不承诺词库已经降低错误率。
