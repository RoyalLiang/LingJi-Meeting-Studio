# 重点标题、会后收尾提示与 Windows 自动会议

日期：2026-10-31。v0.2.5 候选，基线 v0.2.4 / d30da26。用户确认问题发生在 Windows，应用仍打开、使用 ASR＋LLM；后台实际继续处理，但页面没有相关提示。这里不把缺少提示写成已证实的后台取消。

## 本轮验收

1. 重点速览大标题使用综合主题节点生成的 `minutes.title`，随新轮标题更新；所有 highlights 仍完整列在正文，不用第一条事实充当标题。提示词要求综合历史及本轮节点，形成简洁议题标题。
2. 录音封存、待传尾段、尾段转录、排队/运行中的纪要，应持续显示收尾状态和节点进度。完成后才显示收好；失败显示待重试，保留已有重点。收起重点面板不影响录音控制区提示。
3. 封存时有新转录则立即申请尾端会中检查点，绕过会中刷新间隔；已有任务保留。分钟处理队列优先结束会议，保留单场串行、引用版本、人工保护和重试退避。
4. Windows 新增 Chrome/Edge、飞书的后台输入/输出会话监听，复用默认关闭、十秒开始、三十秒结束、取消与自动记录归属规则；不新增录音或云分析授权。

## Windows 的具体边界

- 在专用 MTA 线程持久保存全部活动 render/capture 端点的 session manager；注册通知后首次 GetCount，通知保留接口引用并合并到会话表，Expired 会话释放。
- 按会话 Active 状态、PID 与进程映像文件名归属，排除本进程。不是音量检测，也不是发布者签名认证。
- PID/路径不明、跨进程会话仅返回初始 PID、读失败、设备为空和拓扑变化均不提供正常停止证据。已知选中活动仍可提供正例；其余不确定情况重置停止倒计时。
- 自动启停仅适用于可观察的**共享音频会话**。正常共享会话均停止/过期后，可进入结束候选。WASAPI 会话接口不覆盖独占流；切换到独占模式可能不可观察而误结束，这是明确不支持的场景，不能宣称已排除此风险。独占场景需手动控制或更可靠的会议状态信号。
- 其他标签页播放、飞书的非会议音频、设备切换仍可能误触发或延迟结束；退出应用后不继续监听。

## 验证层次

使用真实组件/调度函数构造失败回归，再修复：长句误作标题、封存后等待正常间隔、终稿运行中显示已完成、本机尾包尚未到服务端时缺提示。另验证多会议的收尾优先序和在途任务保留。

Windows SDK 类型检查使用官方 Rust Windows 目标；CI 会编译完整产品，执行实际 MMDeviceEnumerator 只读初始化与通知空指针边界。它们不打开采集流，也不等于真实 Chrome/飞书会议测试。真实共享音频活动、独占模式、设备切换与误触发率单独列为未验收。
