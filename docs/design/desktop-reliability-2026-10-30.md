# 桌面保存、设置、启动与悬浮框验收

来源：2026-10-30 用户本轮要求。实施基线 `baf38944937276778a5b2cdbb9f3762360f4f90e`（v0.2.1 产品代码），另合并本轮已完成的 Beta 分享回执。以下为本轮范围与验收目标，不代表所有平台实机已验。

## 用户要求

1. 修正 macOS 结束会议后持续显示原音保存中、长时间读取波形，以及设置显示和操作卡顿。
2. 按现有实现核对 macOS 与 Windows 差异，修正相关缺陷，并优化 macOS、Windows、Linux 三端启动加载。
3. 缩短最小化悬浮框，修正麦克风启用/禁用显示。
4. 悬浮框保持工作区顶部居中、始终置顶，并保留美观间距。

## 本轮实现约束

- 完整记录快照按服务端 cursor 单调接受；较早的 GET 或结束响应不能回退已持久化、已结束或已清理状态。新建、结束、刷新和订阅共享同一完整快照入口。
- 默认会议列表直接复用 bootstrap 阶段已取得的账户列表；搜索和目录变化仍重新请求。账户允许上传的记录集合保持原有权限边界。
- 设置表单自身的输入、加载和保存正常更新；无关录音信号、时钟与转录父级更新不重复重绘表单。
- 悬浮窗口 340×42 逻辑像素，内容四周留 2px，工作区顶部留 16 逻辑像素；按主窗口当前显示器的工作区、负坐标和缩放计算水平中心。去掉可拖离顶部的位置入口；首次以主窗口所在显示器定位，显示后以悬浮窗所在显示器跟随工作区变化（避免 Linux 隐藏主窗口查询回落主屏）；复用现有每秒状态同步，仅在实际位置偏离时重置，不新增计时器。
- 麦克风开启显示麦克风，关闭显示斜杠；操作提示仍说明下一步动作。短会议使用 MM:SS，超过一小时保留 HH:MM:SS。
- 保留原生落盘确认、重传幂等、停止排空、人工编辑保护与原音留存策略。已清理的原音不能靠状态修正恢复。

## 平台差异与本轮覆盖

| 项目 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| WebView 与用户数据 | WKWebView，按 data_store_identifier 隔离 | WebView2，独立 data_directory，已有后台计时器策略 | WebKitGTK，独立 data_directory |
| 原生音频 | CPAL 平台默认宿主，输出与麦克风显式选择 | CPAL 平台默认宿主，输出与麦克风显式选择 | 优先 PipeWire；系统输出缺少 PipeWire 时明确报错，麦克风可使用默认宿主 |
| 共同持久化链 | 三端共享 Rust 包队列、重采样、前端本地保存后 ACK 和停止排空 | 同左 | 同左 |
| 本轮修正 | 快照、默认列表、设置重绘、图标与悬浮框共用实现 | 同左；原生几何由 CI 实测 | 同左；窗口管理器与真实 PipeWire 另验 |

依据：`apps/desktop/src-tauri/src/main.rs`、`audio/mod.rs`、`recording_widget.rs`、`apps/web/src/App.tsx`。这里不将操作系统权限、声卡驱动或三个 WebView 的性能当作完全一致。

## 验收与边界

- 用实际结束调用路径制造“新持久化事件先到、旧结束响应后到”，再验证实际回放状态；另验证旧 GET 不能恢复已清理状态。
- 保持本地保存/封存与网络上传分离，离线队列与真实待保存录音保护不退化。
- 记录默认列表请求次数和表单重绘次数；启动后台、原生窗口与完整冷启动分别计量。
- 在真实 PCM 的合成双路长录音上检查首次/缓存波形与并发配置读取。当前本机已有记录已清理原音，不能将它标为真实录音性能通过。
- 真实窗口测试检查宽、高、顶部间距及中心偏差；锁屏下的焦点/恢复结果不能作为正常桌面验收。
- 回归、类型、lint、构建、独立评审后，由 GitHub Actions 构建三平台安装包；固定源码、版本与附件摘要，保留失败标签和证据。
