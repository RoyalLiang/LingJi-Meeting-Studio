# 用浏览器把声音变成可核对的会议成果

状态：设计建议；2026-10-11。**已确认约束：浏览器优先、尽量免安装；通用实时语音转录、会议 AI 总结与纪要。**“中文优先、个人及小团队”是本轮规划假设，仍需用户研究验证。

## 产品承诺应落在一次完整记录

人在浏览器中选好声音来源，看到实时文字与保存进度；结束后得到可编辑、能回到原话的纪要。即使采集或网络中断，也能知道记录缺了什么、哪些已安全保存、下一步如何补救。

DeepPage 把 Page 当作持续加工的成果容器。本项目吸收这一理念，使用 **Meeting Record** 把转录、人工笔记、纪要、分歧与行动候选联系起来，而不是首版铺开通用知识库和 Skill 市场。研究事实与未知项见 [DeepPage 报告](../research/deeppage-analysis-2026-10-11.md)。

产品名 TTS 容易被理解为语音合成，建议在对外命名验证中检查识别成本；本轮不更改仓库名称。

## 首版以三个输入途径降低门槛

| 输入 | 用户流程 | 必须给出的边界 |
| --- | --- | --- |
| 麦克风 | 点开始 → 授权 → 检查音量 → 转录 | 听不到远端声音时不能假装正在记录完整会议 |
| 用户选择的标签页/屏幕音频 | 点选择来源 → 浏览器原生选择器 → 检查返回音轨及音量 | 支持受浏览器、系统、来源选择影响；没有音轨时提示换源或使用导入 |
| 音频文件 | 选择文件 → 显示时长/语言/处理位置 → 导入处理 | 不是实时录制；进度、重试、大小与格式限制需明确 |

getDisplayMedia 需要用户主动操作和视频共享授权；`audio: true` 也不能保证存在音轨。实现应只处理明确选择的音频，不编码或上传屏幕视频；为兼容性可能仍需保留原始捕获流到结束，其生命周期必须在目标浏览器实测。依据：[MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)、[Chrome 共享控制](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)。

PWA 安装作为可选便利，不增加声音采集权限，也不承诺关闭页面后继续录音。原生客户端或扩展仅在 Web 无法覆盖的明确场景下评估。

## 让一次使用只有几个主要决定

1. **录前**：选择音源、语言、是否留存原音；清楚显示云处理位置与录音告知。检测没有声音时提供操作指导。
2. **录中**：主要展示转录与人工速记；暂定文字弱化，定稿稳定。持续显示声音来源、断线/待上传时长、已保存进度。实时要点是可关闭的暂定建议。
3. **结束**：立即停止设备采集，页面继续显示“保存中”“整理中”。内容不完整时显示缺口，不用一个模糊的成功提示遮盖。
4. **会后**：按概览、议题、决议候选、行动候选、待澄清事项组织纪要；点击句子跳至对应转录及可用音频。人工修改保留，重生成作为新草稿比较。
5. **带走**：先支持 Markdown/TXT/SRT 与可控分享；精细 PDF、跨会搜索、日历或任务系统集成随后按需求加入。分享前可预览范围、有效期和撤销方式。

空状态优先解释下一步。错误显示在页面，提供重试和恢复路径；复制或导出失败给出手动方式。不要以 native alert/prompt 代替产品反馈。

## 将首版范围压到可交付闭环

**必须完成**：浏览器来源检测、麦克风采集、明确支持范围内的共享音频、导入、实时转录、持久保存与恢复、会后纪要、片段引用、人工编辑、导出、删除与最小身份隔离。

**随后验证**：说话人标签修正、模板、轻量分享、实时翻译、多语言、文件夹与检索。翻译或实时要点失败不得阻塞原文保存。

**延后**：通用 Agent/Skill 市场、GraphRAG、自动知识自增长、自动创建外部任务、会议机器人、全平台原生客户端。它们需要独立需求、质量和权限论证。

## 用结果指标代替功能数量

以下均为**待通过样本校准的建议门槛，不是现有产品成绩**。

| 指标 | 口径 | 建议起点 |
| --- | --- | --- |
| 激活成功 | 首次尝试到成功获得有声输入并显示转录；把权限拒绝/能力不支持单独分桶 | 先收集基线，不预设虚高目标 |
| 有效记录率 | 已开始有声记录中，结束后能恢复所有已承诺持久保存片段且无未告知缺口 | 试点 ≥99%；任何静默丢失必须调查 |
| 首字延迟 | 音频采样位置到浏览器显示对应 partial，同一时基校正 | 稳定网络 P95 ≤800ms，分设备/来源报告 |
| 定稿延迟 | 对应语音结束到已保存 final 可见 | P95 ≤2.5s；与整场停止耗时分开 |
| 纪要就绪 | 音频排空且转录版本封存到草稿可读 | 60 分钟会议 P95 ≤120s，样本校准 |
| 引用正确率 | 经人工检查，引用确实支持该结论的纪要断言/被检查断言 | 高风险决议和行动逐条审核，禁止无依据补人名日期 |
| 实用性 | 用户无需大改即可采用的纪要 / 已评审纪要 | 试点目标 ≥70%，记录修改原因 |
| 识别质量 | 中文 CER、英文 WER、术语召回、重叠语音与说话人错误分别评估 | 建首个真实样本集后再定门槛 |

北极星建议为“每周被用户确认可复用的完整会议记录数”；转录分钟、模型调用量与页面停留只是解释变量。
