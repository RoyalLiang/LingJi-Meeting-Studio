# 90 天实施路线图

- 文档状态：`Draft`
- 更新时间：`2026-03-19`

## 阶段目标

在 90 天内，把仓库从空白状态推进到可供试点用户使用的受限 Beta。

## 阶段一：0-2 周

目标：定义边界，验证最短链路。

交付物：

- `PRD v1`
- `Architecture v1`
- 音频采集技术选型结论
- 至少 2 家 ASR provider benchmark
- 会话、segment、translation 数据模型初稿

退出标准：

- 确认 `Windows + 会议软件` 的采集方案可行
- 确认 partial/final 事件模型可行
- 确认首发场景与非目标

## 阶段二：3-6 周

目标：交付 MVP 主链路。

交付物：

- Desktop 录制器原型
- Session Gateway 可接收音频并返回实时 transcript
- Transcript API 可持久化 session 与 segments
- 基础会话列表与回放页面

退出标准：

- 连续 30 分钟会话稳定
- `P95 partial latency <= 800ms`
- transcript 可在会后回放

## 阶段三：7-10 周

目标：补齐协作能力。

交付物：

- 中英实时翻译
- 浮动字幕
- Live Share viewer
- glossary 上传与命中
- viewer 晚加入补历史

退出标准：

- 分享链接全链路可用
- viewer 中途加入不丢上下文
- glossary 对术语识别有可测改善

## 阶段四：11-13 周

目标：补齐知识化与发布信心。

交付物：

- AI 摘要
- 行动项提取
- 主题分段
- 基础审计日志
- 发布流水线与回归基线

退出标准：

- AI 纪要被试点用户认可
- 关键回归路径可自动化验证
- 发布不依赖单一成员手工操作

## 人员节奏

### 第 0-30 天

- 产品负责人
- 技术负责人
- 后端/实时工程师
- 前端/桌面工程师

### 第 30-60 天

- QA 自动化负责人
- DevOps / SRE

### 第 60-90 天

- 安全与隐私顾问按需接入
- 数据与 AI 顾问按需接入

## 每周节奏

- 周一：书面规划校准
- 周中：架构或设计评审
- 周四：发布准备度检查
- 周五：试点反馈与复盘

## 每周必须看的指标

- 会话启动成功率
- partial/final 延迟
- provider 错误率
- viewer 加入成功率
- AI 纪要接受率

3. 设计 `segment` 标准事件与共享类型
