# 产品扩展文档 v2

- 文档状态：`Draft`
- 更新时间：`2026-03-19`
- 产品代号：`TTS Platform`

## 1. 产品定位升级

当前产品不再只是“实时转录工具”，而是一个面向会议、访谈、培训与跨语种协作的 `实时语言工作台（Realtime Language Workspace）`。

核心承诺升级为：

1. 听得见：实时转录与实时传译
2. 看得清：原文、译文、总结并行可见
3. 收得住：录音、文本、总结、文件夹统一沉淀
4. 带得走：导出 PDF、录音与后续分享
5. 跟得上：悬浮窗与多端观看降低信息丢失

## 2. 本轮新增需求摘要

### 必须进入主线的需求

1. 支持录音实时传译（多语种），并可设置“当前语种默认不转译”
2. 原文与译文同时显示，支持渐进式总结
3. 支持导出录音文件与总结 PDF
4. 支持文件夹 / 目录收录同类内容
5. 实时转录内容使用悬浮窗展示

### 产品含义

这意味着产品从“会话级 transcript”升级为“会话 + 知识资产 + 展示层”的三层结构：

- 会话层：录音、转录、翻译、总结
- 资产层：文件夹、目录、标签、导出物
- 展示层：主界面、悬浮窗、viewer、回放页

## 3. 用户与场景扩展

### 核心用户

- 跨语言会议参与者
- 培训与课堂记录者
- 采访 / 用户研究记录者
- 对实时字幕依赖较高的用户

### 重点场景

#### 场景 A：双语会议

- 用户需要边听边看原文和译文
- 当前说话语言如果已经是自己熟悉的语言，不希望浪费视觉空间重复翻译

#### 场景 B：讲座 / 培训

- 用户需要悬浮字幕持续跟随
- 会后需要录音与总结 PDF 直接归档

#### 场景 C：专题资料积累

- 同类型内容需要进入固定文件夹
- 文件夹级术语、总结和导出应该可复用

## 4. 功能扩展方案

## FE-01 多语种实时传译

### 用户价值

- 用户可以在同一会话里看到多语种说话内容的即时理解结果
- 可以减少跨语种会议中的理解延迟

### 关键规则

- 支持按会话选择 `source language` 与 `target languages`
- 支持“当前语种默认不转译”开关
- 支持 `auto-detect` 与手动指定语种双模式

### 交互要求

- 原文和译文必须并排或上下稳定对齐
- 当“当前语种默认不转译”开启时，原文为当前阅读语言则只显示原文，不重复显示译文

## FE-02 原文 / 译文 / 渐进式总结同屏

### 用户价值

- 用户不只是在看字稿，而是在实时获取更高层次信息

### 关键规则

- 渐进式总结必须是低置信度产物，界面要与 final summary 区分
- summary 更新频率要受控，不能高频跳动导致阅读疲劳
- summary 必须引用最近时间窗口，而不是每次都重写全量内容

### 展示结构

- 左侧：原文 transcript
- 右侧：译文 transcript
- 顶部或侧栏：渐进式总结卡片

## FE-03 导出录音与总结 PDF

### 用户价值

- 会后可直接分发会议结论与存档资料

### 导出物定义

- 原始录音文件或用户允许保存的音频文件
- 总结 PDF
- 可选：transcript PDF / 双语 transcript PDF

### PDF 建议结构

1. 标题
2. 时间 / 时长 / 文件夹
3. 主题摘要
4. 行动项
5. 关键术语
6. 可选 transcript 附录

## FE-04 文件夹 / 目录系统

### 用户价值

- 用户不只在管理单个会话，而是在管理一类知识资产

### 文件夹应该承载的内容

- 会话集合
- 术语表
- 参考资料
- 默认导出模板
- 默认摘要风格
- 权限边界

### 扩展方向

- 文件夹级搜索
- 文件夹级 AI 问答
- 文件夹级总结汇编

## FE-05 悬浮窗字幕

### 用户价值

- 在开会、听课、看视频时无需频繁切主界面

### 要求

- 始终置顶
- 可拖动
- 可切换原文 / 译文 / 双语
- 可调透明度、字号、行数

### 风险

- 悬浮窗不能成为性能热点
- 长文本换行与闪动要受控

## 5. 最强大脑会继续扩展的方向

## 5.1 UI 设计

最强大脑不会只做一个“列表 + 详情”的普通后台，而会明确做三种界面层：

- `Capture Surface`
  - 负责录制、转录、翻译、悬浮窗
- `Knowledge Surface`
  - 负责文件夹、标签、摘要、回放、搜索
- `Share Surface`
  - 负责导出、viewer、PDF、分享链接

关键扩展：

- 双栏 transcript 视图
- summary timeline
- transcript + summary 的可切换阅读模式
- folder dashboard
- export center

## 5.2 AI 转录 / 翻译

最强大脑不会只选一个 provider 然后“希望它全能”，而会做分层：

- `ASR / Interpreting`
  - 实时转录 / 同传
- `Summarization`
  - 渐进式总结 / 会后总结
- `Knowledge Extraction`
  - 行动项 / 术语 / 主题 / 风险点

关键扩展：

- 多 provider 路由
- 语种自适应
- 领域术语增强
- summary 风格模板
- provider fallback

## 5.3 知识管理

关键扩展：

- 文件夹级术语表
- 文件夹级参考文档
- 文件夹级默认语言配置
- 会话级标签与收藏
- 摘要到知识卡片的转化

## 5.4 导出

关键扩展：

- PDF 模板系统
- 导出音频 + PDF 打包
- transcript 导出为 TXT / Markdown / SRT
- 面向企业的统一导出样式

## 5.5 协作

关键扩展：

- viewer 只读链接
- 文件夹级共享
- summary 评论与批注
- 行动项 owner 指派
- 内外部协作权限边界

## 5.6 可观测性

关键扩展：

- provider 成功率 / 错误率
- partial / final latency
- summary 更新时间间隔
- export 成功率
- 悬浮窗崩溃或重连率

## 6. 版本排序建议

### Phase 1：必须先打透

- 实时转录
- 多语种实时传译
- 原文 / 译文同屏
- 悬浮窗字幕
- 渐进式总结

### Phase 2：形成工作流闭环

- 文件夹 / 目录
- 会后总结固化
- 导出录音与总结 PDF
- 文件夹级术语与默认配置

### Phase 3：形成协作与知识资产

- 文件夹级搜索
- viewer / share
- summary 协作
- 文件夹级 AI 问答

## 8. 当前关键取舍

### 应该坚持的事

- 先做实时链路稳定，再做复杂 UI 花活
- 先把 summary 做成可信辅助，再做“智能代理感”
- 先把文件夹做成知识容器，再做复杂知识图谱

### 不应该过早做的事

- 全平台同时上线
- 一次做完所有语种
- 在 transcript 还不稳定时过度依赖 AI 总结
- 过早建设复杂企业后台
