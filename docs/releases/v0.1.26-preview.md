# 聆记 v0.1.26 公开测试版

本版包含持续纪要回显与首字优化、顶部提示裁切修复和设置精简，并隔离播放按钮数字标签对提示层字号与定位的影响。已发布；四项 CI 和十个公开附件核验通过，详见[发布回执](../evidence/preview-v0.1.26-2026-10-27.md)。

## 修复与改进

- 会中多窗口整理时，首个有输出的窗口可提前展示实时正文；并行窗口不拼接预览，最终汇总开始时重置预览流。
- 会中请求失败或失效后，后续转录追加不再把错误隐藏成空白纪要区；保留错误和重试入口。用量改标“模型用量”，与纪要生成状态分开。
- 有转录时首轮自动整理等待最多 30 秒，后续仍按用户配置更新，默认间隔保持 120 秒。
- 明确配置 Kimi K3.1 Pro 模型 ID 时，会中使用 low 思考强度；终稿不覆盖思考强度，其他模型保持原参数。Kimi 纪要请求显式给出 16384 token 输出预算，供思考和正文共同使用。不禁用思考，不把思考原文当成纪要。
- 顶部播放、导出等按钮的提示使用独立显示层，支持视口边缘换行与翻转、键盘与未聚焦悬停的 Escape 关闭、禁用按钮提示，滚动后关闭。
- 设置移除浏览器能力检测、删除统计和用量说明，保留模型、设备、翻译及更新等实际设置。诊断下载收为紧凑按钮，待传音频备份仅有待传数据时显示。

## 验证与安装

本地 Node24 完整回归 518/518，独立相关链路复核 87/87；ESLint、Web 类型检查及构建通过。真实 React 浏览器验证失败提示、首草稿、设置底部和弹层；隔离 macOS 原生验证设置开关、未聚焦悬停的 Escape、小窗、隐藏录音与重启补传。模型输出与音频为显式夹具，没有调用真实 Kimi。

[Actions](https://github.com/RoyalLiang/LingJi-Meeting-Studio/actions/runs/40372834413) 的 verify、build、build_windows、publish 均成功。[v0.1.26 Release](https://github.com/RoyalLiang/LingJi-Meeting-Studio/releases/tag/v0.1.26) 的十个公开附件逐个下载并核对大小、SHA-256、版本和冻结源码来源。

用户已确认模型字段为 `kimi-k3-1-pro-261024`。参数规则依据[火山方舟文档](https://docs.volcengine.com/docs/ark/deep-thinking?lang=zh)；真实供应商首字耗时、16K 预算表现与原会议语义质量仍需实测，不能从本地夹具推断提速倍数。Windows 真机、高 DPI 与原会议现场仍未复验。
