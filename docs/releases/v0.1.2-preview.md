# 聆记 v0.1.2：长会议与录音恢复测试版

本次提供源码和 macOS Apple Silicon 测试安装包，标记为 GitHub pre-release。

## 系统与下载

- Apple Silicon Mac（M 系列），macOS 14.6 或更新系统。
- 下载 `Lingji-0.1.2-macos-arm64.dmg`、`SHA256SUMS.txt`、`release.json` 和安装说明。
- 应用为 **聆记 Preview.app**，版本 0.1.2，macOS bundle 版本 0.1.24，内置 Node 24 后台。

将附件放在同一目录，运行 `shasum -a 256 -c SHA256SUMS.txt`。源码与工作流 SHA、Actions 运行和实际包哈希见 `release.json`。

## 本版变化

- 移除会议累计两小时音频配额，双音轨分别计量也不再提前触发限制；导入同样去除两小时时长限制。此前本地源码的改动首次进入公开安装包。
- 修复共享视频轨结束误触发会议暂停；只监听实际音频轨状态。单路音源丢失时，其他音源继续录制，提示后可重新接入。
- 全部音源丢失时只暂停、保留恢复入口，不自动结束本场；存储故障仍暂停采集并明确提示，以免继续丢失音频。
- 保留中断前已采集尾段，隔离旧录音控制器的回调，避免干扰新会议。
- 包含已确认的 C 版一体会议头部、气泡提示、图标工具栏、齿轮整理设置和跨音源上传调度优化。
- 包含可选 OpenAI Realtime 原音理解，默认仍用 ASR＋LLM；启用需要独立配置与本场授权，详见[启用说明](https://github.com/RoyalLiang/LingJi-Meeting-Studio/blob/v0.1.2/docs/engineering/openai-realtime.md)。
- 项目规则要求每轮更新验证后 commit、push，并通过 GitHub Actions 后台构建和发版。

## 升级与数据

先暂停或结束录音、等待待传队列排空、退出旧应用并备份 `~/Library/Application Support/com.tts.meeting`，再替换应用。Preview 与 Alpha 使用相同应用标识，不要同时运行。

本版需要实际安装并重启到 0.1.2；旧的 0.1.1 应用进程仍执行原有两小时限制。升级不恢复已经过期清理的音频，也不修改已保留会议的授权。

无两小时时长配额不代表无限存储：本机待传音频仍有 48 MiB 容量保护，单文件导入最多 64 MiB，单场片段与音源数仍有资源保护。断网过久或磁盘故障可安全暂停，不能宣称无限录制。

## 签名与验证边界

**ad-hoc 签名，未经 Developer ID 签名或 Apple 公证。** 首次启动按 macOS 的隐私与安全设置允许此测试应用。

由 GitHub Actions 的 macOS ARM runner 构建。成功的构建和发布任务才证明安装包已交付；运行结果以 Release 附件和 Actions 回执为准。本地验证见[修复记录](https://github.com/RoyalLiang/LingJi-Meeting-Studio/blob/v0.1.2/docs/evidence/recording-unlimited-recovery-2026-10-22.md)。

三小时双音轨验证使用合成元数据，录音中断测试使用浏览器与原生接口替身。真实麦克风和系统声音的长会议、锁屏/设备切换、真实 ASR/LLM 质量与 Realtime 服务尚未在本轮实测。
