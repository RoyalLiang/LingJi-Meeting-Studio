# 聆记 v0.1.5：豆包音频纪要测试版

提供源码和 macOS Apple Silicon 测试安装包，由后台 GitHub Actions 构建并发布 GitHub pre-release。实际发布状态以 Release 和 Actions 回执为准。

## 系统与下载

- Apple Silicon Mac（M 系列），macOS 14.6 或更新系统。
- 下载 `Lingji-0.1.5-macos-arm64.dmg`、`SHA256SUMS.txt`、`release.json` 和本安装说明。
- 应用为 **聆记 Preview.app**，版本 0.1.5，macOS bundle 版本 0.1.27，内置 Node 24 后台。

将附件放在同一目录，运行 `shasum -a 256 -c SHA256SUMS.txt` 核对。源码 SHA、Actions 运行和实际包哈希见 `release.json`。

## 本版变化

- 新增“豆包音频 · 直接理解＋转录留证”：通过 Responses API 向纪要模型发送音频，ASR 并行提供逐字稿、时间定位和版本引用。
- 支持 `doubao-seed-2-1-lite-260915`，长会议按来源和时间窗口处理；保留原 ASR＋LLM 与 OpenAI Realtime 模式。
- 纪要需要引用冻结的转录片段版本；人工修订仍受保护，服务失败明确提示，待处理任务使用冻结的模型版本。
- 继承已移除的两小时录音上限，以及既有单行播放器、跳转和倍速能力；容量与任务预算保护继续生效。

## 豆包配置

打开“设置与诊断 → 模型与转录服务”：

| 设置项 | 值 |
| --- | --- |
| 会议理解 | 豆包音频 · 直接理解＋转录留证 |
| 模型协议 | Responses |
| 模型服务地址（完整接口） | `https://ark.cn-beijing.volces.com/api/v3/responses` |
| 模型 / 接入点 ID | `doubao-seed-2-1-lite-260915` |
| 方舟 / 兼容模型 API Key | 填写已开通该模型的方舟密钥 |

点击“保存服务配置”，再点击“测试纪要”。密钥在你自己的 App 服务端配置，不随安装包分发。转录服务继续使用原 ASR 地址和语音密钥，方舟模型密钥不能代替语音 ASR 密钥。

新建会议需勾选“自动生成 AI 纪要”，允许本场原音发送；既有会议可在“整理设置”中开启或明确选择手动 AI 整理。音频已过期或已清理的会议不能重放为音频纪要。完整说明见[豆包音频配置](https://github.com/RoyalLiang/LingJi-Meeting-Studio/blob/v0.1.5/docs/engineering/doubao-audio.md)。

## 安装与升级

结束或暂停录音，等待待传队列排空，退出旧应用并备份 `~/Library/Application Support/com.tts.meeting`，再替换应用。Preview 与 Alpha 使用相同应用标识，不要同时运行。升级不恢复已过期清理的音频，也不改变会议留存授权。

将应用拖入“应用程序”。本版仍为 **ad-hoc 签名测试包，未经 Apple 公证**。核对来源和摘要后，可按[Apple 官方单应用授权步骤](https://support.apple.com/en-us/102445)继续测试；安全提示说明见[macOS 安全提示](https://github.com/RoyalLiang/LingJi-Meeting-Studio/blob/v0.1.5/docs/releases/macos-trust.md)。

## 验证边界

真实豆包合成音频探针、纪要模型 worker 工作流和静音连接测试通过；11 项定向测试与 385 项 Node 回归通过。工作流中的 ASR 使用受控测试转录，不能当作真实 ASR 验证。

真实多人会议准确率、真实 ASR 与音频模型的并行实录、多小时设备连续录音、休眠恢复与新 Mac 安装均尚未验收。包体、签名、完整性与隔离启动结果以本版 Actions 和 `package-smoke.json` 为准。详见[音频纪要验证证据](https://github.com/RoyalLiang/LingJi-Meeting-Studio/blob/v0.1.5/docs/evidence/doubao-audio-2026-10-22.md)。
